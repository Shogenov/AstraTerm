Python, GTK, WSL и Linux-ВМ для запуска Windows-приложения не требуются.

Общие изменения по умолчанию выполняются в обеих ОС. Единый manifest — `shared/product.json`; рекомендуемые [три сценария сборки](../docs/BUILD.md) и [архитектура](../docs/ARCHITECTURE.md) находятся в корне проекта.

## Запуск и сборка

Цель поставки — Windows x64 с Windows ConPTY. Для разработки используются Node.js 22 и npm. Выполните в PowerShell из каталога `windows`:

```powershell
npm ci
npm test
npm start
```

`npm ci` использует зафиксированный `package-lock.json` и загружает npm-зависимости, Electron и терминальный native-модуль. Установка и сборка требуют доступа к соответствующим серверам. Для проверки окна и связки renderer/main доступна команда:

```powershell
npm run smoke
```

Для поставки:

```powershell
npm run dist
```

Рецепт сборки создаёт в `../dist/windows/`:

- `AstraTerm-0.6.0-Windows-x64.exe` — portable запуск от обычного пользователя;
- `AstraTerm-0.6.0-Windows-x64.zip` — распаковать целиком и запускать `AstraTerm.exe` из полученного каталога;
- `win-unpacked/` — промежуточное распакованное приложение.

Права администратора, установка Python и изменение службы Windows OpenSSH Agent для запуска не запрашиваются. Папка `win-unpacked` и ZIP содержат несколько необходимых файлов; один `AstraTerm.exe` из неё отдельно не переносится. Подпись исполняемого файла и автоматические обновления пока не настроены. Успешная сборка сама по себе не подтверждает приёмку упакованного приложения.

Исходный архив Windows создаётся отдельно из корня проекта:

```powershell
python tools/package_windows.py
```

Он записывает `dist/windows/astraterm-0.6.0-windows-source.zip`. В архив включаются только исходники Windows, тесты, lockfile, относящиеся к поставке документы и сам упаковщик; `node_modules`, бинарные сборки, локальные настройки и средства доступа к ВМ исключены. Linux-архив `tools/package.py` и `.deb` не меняются.

## Ежедневная работа

Меню находится в крайнем левом углу. Средняя кнопка мыши закрывает вкладку со всеми её терминалами без предупреждения. Перетаскивание вкладки на другую переносит все её панели в разделение рядом, сохраняя процессы и историю. Обычное закрытие крестиком/клавиатурой сохраняет подтверждение.

В 0.5.3 панель можно вытянуть за её заголовок на «+» или свободное место строки вкладок. Перетаскивание объединённой вкладки туда же разъединяет все её панели. Кнопка «+» также открывает новый локальный терминал. ПКМ по вкладке открывает меню: закрыть текущую, все, все кроме текущей; для объединённой вкладки доступно «Разъединить все». Меню привязано к нажатой вкладке, даже если активна другая. Массовое закрытие спрашивает один раз; разъединение сохраняет соединения, историю и выбор MultiExec.

Создайте SSH-подключение или откройте локальный PowerShell. При наличии PowerShell 7 в стандартном каталоге используется он, иначе Windows PowerShell 5.1. Начальный каталог задаётся в настройках сессии; отсутствующий или недоступный каталог вызывает ошибку. Адрес, пользователь и порт SSH задаются явно. Для цепочки шлюзов используйте поле вида `user@gateway:22,user@next-gateway:22`; IPv6 указывается в квадратных скобках. Конфигурация `~/.ssh/config`, `ProxyCommand`, SSH-сертификаты и неявные настройки алиасов пока не интерпретируются.

При запуске PowerShell AstraTerm добавляет эквивалентные сочетания PSReadLine для доступных раскладок только в дочернем процессе. Это сохраняет обычные действия `Ctrl+C` и `Ctrl+Z`, в том числе при русской раскладке. Профили PowerShell, установленные модули, настройки раскладки ОС и ввод других приложений не изменяются.

Создание папки доступно в заголовке списка и контекстном меню. Папки могут быть вложенными и пустыми; общие SSH-настройки наследуются от родителя к потомку. Старые подключения сохраняют индивидуальные значения, пока вы явно не включите применение группы к существующим сессиям. Адрес сервера и удалённая команда индивидуальны. Изменение настроек применяется при новом соединении.

Разделение позволяет перенести уже открытый терминал другого хоста или открыть новое подключение. Общий вид показывает существующие панели рядом. Для MultiExec отметьте нужные панели и включите режим: пользовательский ввод из отмеченной панели идёт только отмеченным работающим получателям, включая источник ровно один раз. Ввод в неотмеченной панели остаётся локальным. Есть выбор всех, снятие выбора и пауза; новые и переподключённые панели требуют новой галочки. Программные макросы и ответы самого терминала не рассылаются. Расширенная приёмка сложных IME и интерактивных программ остаётся отдельной задачей.

В контекстном меню терминала находятся поиск, копирование/вставка, снимок вывода, запись нового вывода активной сессии и переподключение. Запись не восстанавливает ранее прошедший вывод и может содержать управляющие последовательности или секреты, выведенные удалённой программой.

## Ключ с passphrase

Через **«SSH-профили…»** выберите файл ключа из `%USERPROFILE%\.ssh` или другого каталога и задайте профиль по умолчанию либо профиль конкретного подключения. Явно выбранный именованный профиль имеет приоритет; если он не выбран, поле собственного файла ключа в сессии имеет приоритет над профилем по умолчанию. В JSON сохраняются только метаданные: идентификатор, название, путь и публичный отпечаток. Содержимое приватного ключа, пароль учётной записи и passphrase в базу и экспорт не записываются.

Если выбранная идентичность уже доступна в Windows OpenSSH Agent, AstraTerm использует именно её. Для распознавания загруженного ключа без ввода passphrase нужен соответствующий публичный файл `<ключ>.pub`. Системный режим использует имеющиеся ключи агента либо запрашивает пароль серверной учётной записи.

Если выбранного ключа в доступном агенте нет, passphrase запрашивается один раз и ключ разблокируется в памяти приложения. Последующие SSH-подключения используют этот кэш, а SFTP работает в уже аутентифицированном SSH-соединении. После закрытия AstraTerm ключ из памяти удаляется, и при следующем запуске потребуется новая разблокировка. Это отличается от Linux-режима «один раз за сеанс ssh-agent».

AstraTerm не запускает службу агента, не меняет её настройки, не требует повышения прав и не выполняет `ssh-add` автоматически. Для сохранения разблокировки за пределами жизни приложения ключ должен быть заранее загружен пользователем в Windows OpenSSH Agent. Отсутствующий явно выбранный профиль вызывает ошибку и не заменяется произвольным другим ключом.

Первое подключение к неизвестному серверу требует явного подтверждения SHA256-отпечатка. Изменённый или отозванный ключ отклоняется. Приложение учитывает обычные и хешированные записи `%USERPROFILE%\.ssh\known_hosts` и хранит собственные подтверждения отдельно; пользовательский `known_hosts` не переписывается автоматически. Доверие SSH CA пока не реализовано.

## SFTP и редактор

Файловая панель автоматически открывает SFTP активного работающего SSH-терминала. Используется его действующий SSH2-транспорт, поэтому повторный пароль или passphrase не запрашивается. При переключении на другой терминал меняется сервер панели; каталог запоминается для каждого подключения. Сетевые результаты и операции связаны с конкретным клиентом и поколением соединения. За командами `cd`, `su` и `sudo` файловая панель не следует.

Доступны локальные каталоги, загрузка и скачивание одного обычного файла, создание каталога, переименование и удаление отдельных файлов, ссылок и пустых каталогов. Непустые каталоги рекурсивно не удаляются. Запись и передача через символьную ссылку отклоняются; рекурсивная передача, очередь, синхронизация и возобновление пока отсутствуют.

Редактор поддерживает UTF-8 до 2 МиБ и отклоняет двоичные файлы с NUL. Перед сохранением проверяется ревизия, чтобы не затереть внешние изменения. Запись идёт через временный файл; для SFTP без атомарной замены используется резервная копия с откатом. Если резервную копию не удалось удалить, её путь сообщается пользователю. SFTP сохраняет uid/gid/mode либо останавливает запись при невозможности сохранить владельца; Windows сохраняет доступный режим файла. Полное сохранение NTFS ACL, удалённых ACL и extended attributes не гарантируется.

Операции изменения не выполняются одновременно. Во время файловой операции закрытие приложения и исходного терминала блокируется; несохранённые редакторы учитываются при выходе.

## Туннели и дополнительные протоколы

SSH-туннели привязаны к выбранному работающему SSH-терминалу: локальный проброс, удалённый проброс и SOCKS5. Дополнительная аутентификация не нужна. Закрытие или переподключение исходной сессии останавливает связанные туннели; сервер должен разрешать forwarding.

RDP с 0.7.0 открывается внутри вкладки через Microsoft ActiveX и поставляемый нативный помощник. См. [RDP](../docs/RDP.md). X11 forwarding пока не перенесён: профиль с включённым X11 останавливается с явной ошибкой. Mosh, Telnet, Serial и VNC в этой версии Windows не реализованы. Собственный X-сервер и Unix-окружение не поставляются.

## Настройки и перенос из Linux

Данные текущего пользователя находятся в `%APPDATA%\AstraTerm`:

| Файл | Содержимое |
| --- | --- |
| `sessions.json` | Схема 2: подключения, папки, общие SSH-настройки, макросы и профили туннелей. |
| `ssh-profiles.json` | Метаданные локальных SSH-ключей и выбор профиля; приватного материала и passphrase нет. |
| `known-hosts.json` | Подтверждённые публичные ключи серверов. |

Экспорт JSON AstraTerm из Linux импортируется через меню Windows. Схема 1 мигрирует с сохранением собственных SSH-параметров; схема 2 сохраняет дерево папок. Пароли и неизвестные поля отбрасываются. Пути вида `/home/user/.ssh/id_rsa` остаются путями Linux: выберите файл Windows вручную и заново создайте локальный профиль ключа. Экспорт сессий не включает отдельный файл профилей ключей и не переносит доверие серверам автоматически. Неподдерживаемые протоколы могут храниться в импортированной базе, но их открытие даёт ошибку.

Сохранение базы атомарное, с файловой блокировкой и проверкой устаревшей версии. После аварийного завершения может остаться `.sessions.json.lock`: удалять её следует только после закрытия всех окон AstraTerm, затем открыть приложение снова. Не заменяйте `sessions.json` вручную при работающем приложении.

На удалённой системе данные не изменяются. Для повторения заранее задаются переменные `ASTRA_VM_HOST`, `ASTRA_VM_USER`, `ASTRA_VM_PASSWORD`, `ASTRA_VM_FINGERPRINT`, при необходимости `ASTRA_VM_PORT`; реальные значения не включаются в документы, исходники или аргументы процесса.

Финальный `AstraTerm-0.5.0-Windows-x64.exe --smoke-test` запущен от обычного пользователя на Windows 11, сборка 26300: процесс завершился с кодом 0, отчёт `dist/windows/validation-portable/report.json` содержит `packaged: true` и `result: PASS`. В готовом EXE прошли основные GUI-сценарии выше, включая отдельные профили туннелей с собственными ID и захваченным SSH-хостом. Второй запуск того же portable EXE с принудительным fallback на Windows PowerShell 5.1 также завершился с кодом 0 и `PASS`: `dist/windows/validation-portable-ps51/report.json`. PowerShell 7 для запуска не обязателен. Проверены CRC всех 324 элементов ZIP, совпадение исходников/иконок в ASAR с финальными файлами проекта и отсутствие пользовательских данных/инструментов разработки в поставке. Это проверка на машине разработки; чистая Windows без установленной среды разработки отдельно не проверена.

Реальный RDP проверен на тестовом Windows 11; проверка прочей независимой инфраструктуры, чистая Windows, подпись и автоматическое обновление остаются в [плане](../docs/ROADMAP.md#windows-050-перенос-и-отдельная-приёмка).
