# Состояние активной машины и учётные данные

С 0.9.0 нижняя строка обеих версий показывает hostname, CPU одним процентом, занятую/общую ОЗУ, отдачу ↑, загрузку ↓, uptime, пользователей с количеством сеансов и заполнение корневого/подключённых дисков. Активная панель определяет машину; для RDP строка скрыта. Полные значения сокращённого текста доступны в подсказке.

## Получение показателей

- Linux локально: чтение `/proc`, utmp и `statvfs`, без команд в терминале. SSH: те же данные через SFTP. Поддерживается Linux на удалённой стороне, включая старый MemFree/Buffers/Cached вместо MemAvailable.
- Windows локально: Node `os` для CPU/RAM/uptime, фоновый штатный PowerShell для сетевых счётчиков, смонтированных томов и WTS-сеансов. Администратор, WinRM и отдельный агент не нужны. Скрипт только читает данные, запускается без видимого окна и ограничен таймаутом.
- Windows SSH: отдельный SFTP-канал в том же проверенном SSH-транспорте. Он не открывает новое подключение и не запрашивает пароль. Его таймаут не закрывает канал файловой панели.
- Linux SSH: переиспользуется готовый SFTP файловой панели, включая OpenSSH fallback. Общая блокировка ввода-вывода исключает пересечение запросов с файловыми операциями. Статистика уступает занятой файловой панели и проверяет endpoint/auth generation.

Обновление — примерно раз в 3 секунды; дополнительные локальные Windows-счётчики собираются реже. CPU и скорость сети требуют двух замеров. При смене интерфейса, сбросе счётчика или большой паузе скорость начинается заново. Для сети выбираются интерфейсы маршрута по умолчанию; если Linux не сообщает маршрут, используются доступные нелокальные интерфейсы. Это счётчики машины, а не трафик одного SSH-подключения.

`—` означает отсутствие доступа/поддержки или ещё не полученный замер, а не нулевую загрузку. CPU не включает повторно guest ticks. Linux-память использует MemAvailable с резервной формулой для старого ядра. Заполнение Linux-диска соответствует used/(used+available), как `df`; виртуальные файловые системы исключаются. Размеры — двоичные КиБ/МиБ/ГиБ. Пользователи Linux определяются по записям USER_PROCESS в glibc x64 utmp; это системные сеансы, не число вкладок AstraTerm. Windows использует WTS-сеансы, включая отключённые, но ещё не завершённые.

Чтение ограничено размером, списком до 32 Linux mount points и таймаутами транспорта. Недоступные/медленные сетевые файловые системы могут не дать показателей; статистика не должна блокировать интерфейс. Смена фокуса/переподключение отбрасывает устаревший результат. Секреты и произвольные удалённые команды в сбор статистики не входят.

## Общее хранилище

Меню «Инструменты → Хранилище учётных данных» объединяет профили SSH-ключей и пароли SSH/RDP. У строк есть значки протоколов; старые импортированные парольные профили без типа остаются совместимыми с обоими и показывают два значка.

«Добавить» позволяет выбрать SSH/RDP и пароль либо SSH-ключ. Для ключа сохраняются только прежние метаданные в `ssh-profiles.json`: сам ключ остаётся на диске, passphrase разблокирует агент/кэш приложения по прежним правилам. Парольные профили сохраняются в зашифрованном `credentials.vault.json` под мастер-паролем. Их список виден после разблокировки. Блокировка паролей не выгружает ключи из пользовательского ssh-agent.

Поле `protocol` внутри зашифрованной записи необязательно: `ssh`, `rdp` или `both`; старые ID и ссылки сессий не меняются, envelope/KDF остаются прежними. При изменении парольного профиля пустое поле сохраняет прежний пароль. Выбор профиля в сессии фильтруется по протоколу; backend повторно проверяет совместимость. Удаление используемых профилей блокируется, в том числе для ключей, назначенных группе. Приватный ключ, passphrase и пароль не попадают в JSON-экспорт сессий.

## Карта реализации и проверки

Linux: `host_stats.py` — парсеры/замеры, `host_stats_ui.py` — фоновая строка, `credential_dialogs.py` — общий менеджер. Windows: `backend/host-stats.cjs`, `host-stats.ps1`, `renderer/host-stats.js`, `app.js:vaultDialog/editCredential`, IPC `host:stats`, `vault:save/delete`.

Общие сценарии: `shared/contracts/host-stats.json`, `credential-types.json`; проверки — `tests/test_host_stats.py`, `test_vault.py`, Windows `host-stats.test.cjs`, `vault.test.cjs`. GTK: `smoke_status.py` и реальный SSH/SFTP в `smoke_auth_profiles.py`. Windows smoke проверяет локальный CPU/RAM, SSH-статистику без ввода/повторной авторизации и настоящую форму создания RDP-профиля со скрытым паролем.
