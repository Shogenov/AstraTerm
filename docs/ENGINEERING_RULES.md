# Подробные инженерные правила

Читать только разделы, относящиеся к задаче. Общая политика и короткий вход — в [agent.md](../agent.md). Общие изменения по умолчанию выполняются в обеих версиях.

## Совместимость

- Целевая среда: Astra Linux SE 1.6 x86-64, Python 3.5.3, GTK 3.22, VTE 0.46 и штатный OpenSSH.
- На проверенной ВМ команда `python3` указывает на другой Python. Запускать приложение через `scripts/astraterm` или `/usr/bin/python3.5`; системные alternatives не менять.
- Исходники приложения должны разбираться Python 3.5. Не использовать f-строки, dataclasses, аннотации переменных и API, появившиеся только в новых версиях Python/GTK/VTE.
- Платформенные адаптеры находятся в `astraterm/` и `windows/`. Единый номер релиза задаёт `shared/product.json`; зеркала обновляет `tools/sync_shared.py`. Изменения общего поведения вносятся в обе версии. GTK/VTE и `.deb` проверять в Linux; Node/Electron-проверки Windows не подтверждают работу GUI на Astra и наоборот.
- При обновлении development-копии на ВМ детерминированным архивом очищать её кэш `__pycache__` перед проверкой: нормализованный mtime и одинаковый размер изменённого `.py` могут оставить старый байткод допустимым. Не очищать системные каталоги Python.
- Зависимости выбирать из совместимых пакетов целевой Astra. Не подменять системные библиотеки и не обновлять ОС ради одной функции приложения.

## Правила реализации

### Windows-порт

- Изменять платформенные части отдельно; правила Python 3.5/GTK/VTE ниже относятся к Linux. Схема сессий 2, семантика папок и безопасность данных общие. Не переписывать Linux ради Windows-бэкенда.
- Сохранять настоящий Windows ConPTY для PowerShell и SSH2 PTY для SSH; терминал рендерит xterm.js. Не заменять его текстовым полем. Учитывать поколения подключений, завершение ConPTY и принадлежащие процессу workers; не убивать по устаревшему PID.
- `TerminalManager.dispose()` возвращает ожидание собственных ConPTY output workers, включая уже закрытые вкладки. `main.finish()` обязан дождаться его до уничтожения окна/app.exit: node-pty завершает drain примерно за секунду. Ограничение ожидания — 3 секунды до terminate своего worker; не заменять ожидание произвольным sleep или сигналом по PID.
- Начальный каталог PowerShell проверять до запуска; не игнорировать недоступный путь молча. Исправления PSReadLine для русской/других раскладок применять только в дочернем процессе: эквивалентные `Ctrl`-сочетания не должны менять пользовательский профиль, модули и настройки раскладки ОС. Сохранять проверки PowerShell 7 и fallback Windows PowerShell 5.1, включая `Ctrl+C`/`Ctrl+Z` и прерывание команды.
- Renderer работает без Node.js, с context isolation и sandbox; системные действия выполняются через проверяемые IPC main-процесса. Не добавлять удалённые скрипты, `eval`, произвольный shell или небезопасную навигацию.
- SFTP использует `sshClient` текущего работающего SSH-терминала, а не новое соединение с отдельным паролем. Все отложенные ответы и файловые операции привязывать к terminal ID, конкретному SSH-клиенту и поколению; смена фокуса не меняет адрес назначения уже начатой операции.
- Для именованного ключа переиспользовать именно выбранную идентичность Windows OpenSSH Agent. При её отсутствии допустим явно описанный кэш разблокированного ключа в памяти AstraTerm до выхода; passphrase, приватный материал и открытые пароли на диск/в argv/окружение не записывать. Не устанавливать и не запускать службу агента с повышением прав и не выполнять `ssh-add` без отдельного пользовательского действия.
- Явный именованный профиль имеет приоритет; если он не выбран, собственный файл ключа сессии должен использоваться раньше профиля по умолчанию. При импорте и редактировании сохранять известные Linux-протоколы и текущие кодировки, даже если Windows не может открыть такой протокол. Пустой или неверного типа протокол отклонять, отсутствие поля допускает прежний SSH по умолчанию.
- Windows не интерпретирует OpenSSH config: использовать явные host/user/port и цепочку шлюзов. Неподдерживаемый X11 должен давать ошибку; обязательный маршрут не отбрасывать. RDP использует нативную дочернюю поверхность; правила lifecycle и паролей — `RDP.md`; VNC/Mosh/Telnet/Serial пока не заявлять.
- Положительные галочки MultiExec, запуск в выключенном режиме, локальный неотмеченный источник и сброс выбора при reconnect обязательны. Только помеченный человеческий ввод становится рассылкой; ответы xterm.js и программный ввод остаются локальными. Вставку применять отдельно к терминалам ради их bracketed paste и кодировки.
- Хранить Windows-данные в `%APPDATA%\AstraTerm`; схема 2 совместима с Linux, профили ключей и доверие сохраняются отдельно. Не преобразовывать Linux-пути к ключам незаметно а обычный JSON-импорт не принимает секреты. Специальный импорт паролей сохраняет их только в отдельном шифрованном хранилище под мастер-паролем по явному запросу пользователя; правила — `IMPORTS.md`. Атомарная запись, блокировка, проверка устаревшей базы и сохранность исходного файла при неудаче обязательны.
- Сохранять однофайловые границы удаления/передачи, запрет записи через неоднозначные ссылки, ревизии редактора и откат. Предупреждения об оставшейся резервной копии показывать пользователю. NTFS ACL и удалённые ACL/xattrs полностью не гарантировать без отдельной реализации и проверки.
- Тесты Windows запускать через `npm test` из `windows/`; GUI — через `npm run smoke`. Сборка `npm run dist` создаёт portable EXE/ZIP, а `python tools/package_windows.py` — отдельный allowlist-архив исходников. Успешную сборку не выдавать за запуск готового EXE.

### Терминал и процессы

Дублирование вкладки создаёт новые PTY/соединения, сохраняя дерево/порядок и исходные процессы; получатели MultiExec и файл записи не копируются. Переподключение использует текущую сохранённую сессию/наследование и готовит аутентификацию до остановки прежнего процесса; не заменяет тип терминального виджета. Scope — нажатая вкладка, не глобальный фокус после ожидания. Подробности и тесты — [TAB_SESSION_ACTIONS.md](TAB_SESSION_ACTIONS.md).

- Сохранять полноценный VTE/PTY. Не заменять терминал текстовым полем или собственным неполным ANSI-парсером.
- Для VTE 0.46 использовать доступный `spawn_sync`; `spawn_async` появился позже. VTE самостоятельно отслеживает порождённый процесс: не добавлять второй `waitpid`/child watcher для того же PID.
- Не сигнализировать завершённому процессу по сохранённому старому PID. Закрытие и переподключение должны освобождать процессы и дескрипторы.
- Сохранять исправление завершающего вывода быстрых процессов: дополнительный PTY-дескриптор читается после отсоединения VTE от PTY, в неблокирующем режиме и с ограничением объёма. В режиме Linux `TIOCPKT` первый байт каждого чтения — служебный; передавать только данные пакетов с нулевым заголовком. Дескриптор закрывать при завершении и закрытии панели.
- Проверять вывод с учётом асинхронного разбора VTE. `get_text()` возвращает видимую область; для проверки всей истории использовать сохранение scrollback после обработки GTK-событий.
- Кодировки, русская раскладка, специальные клавиши и bracketed paste должны проверяться на целевом VTE, а не предполагаться работающими.

### MultiExec

- Реализован явный живой режим с общим видом существующих терминалов и положительной галочкой у каждой панели. При запуске он выключен; новые, завершённые и переподключённые панели не должны автоматически входить в прежнюю группу. Неотмеченный источник работает локально.
- Только пользовательский клавиатурный ввод в отмеченном VTE становится источником рассылки. `feed_child`/`feed_child_binary` сами вызывают `commit`: сохранять подавление программной отправки и защиту от рекурсии. Ответы терминала, mouse/focus reports и ввод в полях GTK не рассылать.
- Сигнал `commit` VTE 0.46 содержит байты в кодировке источника. Сохранять native bridge, проверку длины/NUL и строгую перекодировку получателям; ошибки не должны выводить введённый текст в диагностику.
- Вставлять CLIPBOARD/PRIMARY нативно в каждый отмеченный терминал, чтобы сохранить его кодировку и bracketed paste. VTE 0.46 не имеет публичного API отмены нативного запроса; завершение без `commit` возможно. Если при переподключении остаётся такой запрос, прежний VTE отключается от ввода и MultiExec, сохраняет точную историю и свой старый процесс до закрытия. Новое соединение открывать в отдельной неотмеченной вкладке с тем же профилем, без автоматического переноса записи в файл. Не подключать новый PTY к старому VTE и не заменять это вечной блокировкой переподключения. При отсутствии нативного ожидания сохранять штатное переподключение; собственные preflight callbacks отменять до нового запуска.
- Старая нижняя строка «Команда / В отмеченные / Выполнить» удалена по просьбе пользователя. Команды вводятся непосредственно в терминалах; для MultiExec служат верхняя панель и галочки получателей. Макросы и программные вызовы остаются локальными. В живом режиме подтверждения на каждую клавишу не добавлять.
- Общий вид и перемещение существующей панели не должны уничтожать VTE, менять процесс/PTY или терять историю. При выходе из общего вида восстанавливать вкладки, раскладку и фокус.
- Обычная кириллица и UTF-8/CP1251 поддерживаются. Сложные асинхронные IME пока не поддержаны; незавершённую расширенную приёмку `ME-01` не объявлять выполненной по наличию интерфейса.

### GTK и файловые операции

- Сохранять компактную нативную компоновку GTK 3.22: штатная рамка Fly и одна верхняя панель действий, все прежние пункты меню доступны через кнопку слева. Для меню используется совместимый с целевой средой `Gtk.Menu.popup`. Использовать отступы и тональные поверхности вместо дополнительных полос и тяжёлых рамок; основной акцент — мятный на графитовом фоне.
- Кнопки со значками должны иметь понятные подсказки и доступные имена; не терять прежние действия и сочетания клавиш при упрощении интерфейса. Создание папки находится в заголовке списка и контекстном меню, изменение подключения — в контекстном меню.
- Кнопка MultiExec остаётся видимой в верхней панели. Панель массового выбора показывать только в общем виде; положительную галочку получателя размещать в компактном заголовке панели, без отдельной нижней полосы. Единственный терминал не должен дублировать заголовок вкладки, а разделённые панели и общий вид сохраняют заголовки. Пауза не сбрасывает выбранных получателей.
- Сетевые запросы и длительные операции выполнять вне главного потока; менять GTK-виджеты через главный цикл, например `GLib.idle_add`.
- При закрытии/смене сессии учитывать устаревшие callbacks и закрывать всю цепочку SSH-транспортов. Не применять результат операции к другому серверу.
- Сохранение редактора и перезапись файлов выполнять через временный файл с сохранением исходного либо возможностью отката. Не терять предупреждения об оставшейся резервной копии.
- Главный выход должен проходить через проверку незавершённых файловых операций и несохранённых редакторов.
- Рекурсивные операции добавлять отдельно с определённой политикой символьных ссылок, конфликтов и отмены; не расширять текущий одиночный Delete до рекурсивного незаметно.
- Колесо над видимой полосой заголовков меняет только горизонтальное смещение полосы в пределах её ширины. В GTK заголовки в отдельном TabStrip, страницы в Gtk.Notebook со скрытыми заголовками. Два средних щелчка в одном терминале выделяют диапазон средствами терминального виджета. Жест не отправляет ввод в PTY и MultiExec.
- Средняя кнопка по заголовку закрывает всю вкладку без подтверждения — явное требование пользователя. Обычный крестик/клавиатурное закрытие сохраняют прежний вопрос. Перетаскивание вкладки на другую переносит все её панели в разделение справа, сохраняя процессы, историю, поколения и выбор MultiExec. Отклонять self/stale/external drops; GTK завершает DND до изменения родителей, Windows сохраняет DOM источника во время drag. Настоящие pointer tests запускать в отдельном Xephyr, а не на рабочем дисплее пользователя. Обратный drop панели в строку вкладок/на «+» отделяет одну панель, drop объединённой вкладки разъединяет все. Приём существующего TerminalPane не должен создавать лишний процесс. ПКМ захватывает ID/объект нажатой вкладки; после подтверждения повторно проверить его существование. Массовое закрытие фиксирует список вкладок до ожидания и спрашивает один раз. Разъединение из меню сохраняет глобальный фокус, из жеста фокусирует вытянутую панель.

### Подключения и данные

- Импорт сторонних файлов: безопасный разбор, предварительный просмотр без секретов, стабильные ID профилей/сессий. Пароли только в `credentials.vault.json` под мастер-паролем; библиотечный AES-GCM/PBKDF2, общие параметры в product, новый nonce при каждой записи, atomic/lock/revision. Мастер-пароль не сохранять, PBKDF2 выполнять вне GTK-потока. Не пересылать пароль конечного узла шлюзу или OTP-приглашению. Непереносимый обязательный маршрут блокирует подключение до проверки. Импортированные команды/скрипты не исполнять.

- Передавать команды клиентов списками аргументов без локального shell. Исключения — явно заданная пользователем удалённая shell-команда и существующая запись через `script`; сохранять корректное экранирование.
- Проверять host/port/user/jump и остальные поля через общую валидацию `core.py`.
- Сохранять проверку ключей SSH-серверов и сертификатов. Не добавлять постоянный `AutoAddPolicy`, `StrictHostKeyChecking=no` или автоматический пропуск TLS/RDP-сертификатов.
- Пароли, ключи, токены и данные доступа к конкретной ВМ не записывать в исходники, инструкции, экспорт, журналы и аргументы процессов. Параметры инструментов разработки брать из окружения/ввода; не выводить секреты в диагностику.
- Профили ключей хранить отдельно от базы сессий в `ssh-profiles.json`: только идентификатор, название, путь, публичный отпечаток и настройки выбора. Сохранять права `0600`, атомарную запись, блокировку и защиту от устаревших изменений. Не добавлять приватный материал/passphrase в этот файл или экспорт сессий.
- При генерации SSH-ключа хранить временные файлы в защищённом каталоге внутри `~/.ssh`. Размещать пару через ссылки без перезаписи. Откатывать созданные файлы, если профиль не сохранён. Linux подаёт парольную фразу в stdin `ssh-keygen`, Windows использует отдельный worker SSH2. Копирование в буфер берёт только проверенную публичную строку из `.pub`.
- Для ключа с passphrase использовать `ssh-agent` и одноразовый askpass-канал с проверкой локального пользователя. Не передавать passphrase в argv или окружении. Агент и `ssh-add` вызывать вне GTK-потока; при отмене/закрытии окна не применять устаревшие callbacks. Повторное подключение должно переиспользовать загруженный ключ; недоступный явно выбранный профиль не заменять произвольным другим ключом.
- Для именованного профиля терминала сохранять проверку итоговой конфигурации через `ssh -G`. Передавать разрешённые фактические сервер, пользователя и порт файловой панели, сохраняя исходное имя/конфигурацию в терминале. Дополнительные идентичности/сертификаты, `HostKeyAlias` и `ProxyJump`/`ProxyCommand` пока требуют системного режима. Не отключать конфигурацию OpenSSH через `-F /dev/null`, не отбрасывать обязательный маршрут и не заявлять полный интерпретатор конфигурации или согласованную политику ключа для цепочки до отдельной реализации.
- SFTP следует серверу активного SSH-терминала и переиспользует ограниченный кэш соединений и каталогов. Сначала пробовать ключ или агент. Запрос учётных данных допустим после ошибки аутентификации. Фиксировать сервер операции независимо от смены фокуса. Сброс на терминал фиксирует каталог из OSC 7 или заголовка оболочки и поколение подключения. Отсутствие или несовпадение каталога завершает операцию до записи. Сброс на файловую панель использует её каталог. Команда `cd` обновляет путь терминала для последующего сброса.
- Резервный OpenSSH обслуживает прямой SFTP, когда Paramiko не согласует серверный ключ или не может выполнить вход ключом. После ошибки входа повторная попытка использует только publickey, сохраняя заданный файл, выбранную идентичность и сокет агента. Пароль из хранилища в эту попытку не передавать. Ручной секрет допустим только для запроса passphrase указанного файла. Парольные профили без ключа сохраняют выбранный метод. Проверку `known_hosts` выполнять при каждом соединении. Неизвестный сервер требует подтверждения, изменённый ключ отклоняется. Для цепочек шлюзов сохранять обязательный маршрут.
- Сохранять whitelist полей, атомарную запись JSON, права `0600`, файловую блокировку и обнаружение устаревшей версии базы. При изменении формата добавить миграцию и проверку старой конфигурации.
- База сессий использует схему 2 с явными вложенными/пустыми группами. При чтении схемы 1 выводить папки из прежних путей, сохранять собственные параметры прежних подключений через `inherit_group_ssh=False`; новые подключения создаются с `True`. Импорт старого формата не должен стирать настройки существующих папок.
- Общие параметры группы — только `username`, `port`, `key_file`, `identity_profile`, `jump_host`, `x11`, `compression`, `encoding`; объединять частичные значения от корня к потомку для SSH/Mosh с включённым наследованием. Не наследовать адрес, ID, имя и команды. Перед запуском терминала, выбором ключа и SFTP использовать одинаковую разрешённую сессию, проходящую валидацию.
- Применение общих настроек к существующим подключениям включается явно отдельной галочкой, по умолчанию снятой. Изменения действуют при новом подключении; работающие терминалы не перенастраивать. Сохранять индивидуальные значения при переключении наследования в диалоге.
- Переименование/перемещение папки, её потомков и ссылок подключений выполнять одной транзакцией с проверкой конфликтов и откатом. При удалении поддерева сохранять подключения в родителе, фиксировать прежние действующие SSH-параметры и выключать у них наследование. Сохранять идентичность перемещаемых папок; повторное создание старого пути не должно использовать их ID.
- Неподдерживаемую политику SSH нельзя молча отбрасывать, создавая прямое подключение вместо требуемого шлюза.

## Проверки и поставка

Выбирать проверки по изменению; для одной правки текста не запускать сетевые подключения или весь GUI-набор.

Модульные тесты:

```sh
/usr/bin/python3.5 -m unittest discover -s tests -p 'test_*.py'
```

Изменения терминала, событий ввода, разделения и жизненного цикла проверять в графическом сеансе Astra:

```sh
DISPLAY=:0 /usr/bin/python3.5 tests/smoke_gui.py
DISPLAY=:0 /usr/bin/python3.5 tests/smoke_multiexec.py
DISPLAY=:0 /usr/bin/python3.5 tests/smoke_identity_dialogs.py
DISPLAY=:0 /usr/bin/python3.5 tests/smoke_groups.py
DISPLAY=:0 /usr/bin/python3.5 tests/smoke_ui_helpers.py
```

Для сетевых изменений доступны `tests/smoke_network.py` и `tests/smoke_multiexec_network.py`. Они используют локальный SSH-сервер ВМ; пароль задаётся в окружении `ASTRA_TEST_PASSWORD` или stdin, имя пользователя — при необходимости `ASTRA_TEST_USER`. Не вписывать реальные значения в команды, сохраняемые в документации. Проверка localhost не подтверждает работу произвольной внешней сети, RDP/VNC-сервера или serial-устройства.

Компоновку и доступность действий проверять через `tests/smoke_design.py`: окно шириной 1024 пикселя, все прежние пункты меню, скрытые дублирующие заголовки, получатели и групповые действия общего вида, пауза и сохранность PTY. Если основной рабочий стол заблокирован, использовать отдельный тестовый дисплей, например Xephyr, чтобы блокировщик не влиял на графические события теста.

Изменения профилей/askpass проверять через `tests/smoke_identity_dialogs.py` (GTK с имитацией агента) и `/usr/bin/python3.5 tests/smoke_ssh_agent.py` (настоящий отдельный агент и синтетический зашифрованный ключ). Не использовать для автотестов реальные пользовательские приватные ключи и не удалять ключи из пользовательского ssh-agent ради подготовки проверки.

Для совместной приёмки SSH/SFTP профилей доступен `DISPLAY=:0 /usr/bin/python3.5 tests/smoke_auth_profiles.py`: тест запускает отдельный loopback `sshd`, отдельный агент и временные ключи/настройки. Парольная аутентификация тестового сервера отключена, чтобы успех подтверждал использование выбранного ключа. Не заменять это чтением реальных пользовательских ключей или изменением их `authorized_keys`/`known_hosts`.

Вариант `DISPLAY=:0 ASTRA_TEST_ED25519_HOST=1 /usr/bin/python3.5 tests/smoke_auth_profiles.py` проверяет тот же GUI-путь с серверным Ed25519-ключом и резервным OpenSSH-транспортом. Сохранять оба варианта: стандартный Paramiko и резервный транспорт должны одинаково применять профиль, авто-SFTP и кэш без повторной passphrase.

Для резервного транспорта запускать `DISPLAY=:0 /usr/bin/python3.5 tests/smoke_sftp_ed25519.py`. Изолированные loopback-серверы проверяют согласование серверного Ed25519 и ошибку Paramiko `BadAuthenticationType` на сервере, который принимает только ключи. Проверяются выбранная идентичность, чтение каталога после входа через OpenSSH, проверка доверия и отмена. Тест использует временные ключи, агент и файлы доверия.

`smoke_groups.py` проверяет настоящий GTK с временной базой, вложенные/пустые папки, наследование и сохранность подключений при изменении дерева; сетевых подключений нет. `smoke_ui_helpers.py` проверяет значки и обычное/плавное колесо над заголовками на настоящем GTK без терминальных процессов и сети. Для общего SSH/SFTP-пути сохранять в `smoke_auth_profiles.py` проверку разрешённых настроек группы вместо заведомо неверных собственных пользователя/порта сессии.

При изменении поведения добавить содержательную регрессионную проверку. В отчёте отличать новые выполненные проверки от результатов предыдущей версии.

Перед выпуском:

1. Обновить фактические возможности в `docs/FEATURES.md`, статусы в плане и нужные инструкции README.
2. Обновить общую версию через `python tools/sync_shared.py --version X.Y.Z`; проверить обе реализации и общие контракты.
3. Собрать исходники: `python3 tools/package.py`; проверить состав архива, исключение секретов, кэшей и инструментов доступа к ВМ.
4. Для поставки `.deb` собрать пакет в Linux через `tools/build_deb.py` и проверить установку/запуск от обычного пользователя. Не считать сборку подтверждением подключения всех протоколов.

## Как описывать результат

Отдельно указывать: что реализовано, что проверено, что остаётся в плане. Внешний клиент RDP/VNC не называть встроенной вкладкой. Не заявлять поддержку сложных асинхронных IME и не объявлять полный паритет с MobaXterm до выполнения критериев из плана.
