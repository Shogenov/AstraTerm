# План развития AstraTerm

В 0.10.0 реализованы публикация подписанных stable-релизов/сайта и пользовательская установка обновлений для обеих ОС; [контракт и границы](UPDATES.md). Будущая работа: delta-пакеты, prerelease-каналы, Authenticode, полная смена многокомпонентного Windows ZIP и автоматический перезапуск Linux после системной установки. Их не считать реализованными.

В 0.9.1 в ПКМ по вкладке добавлены дублирование всех её соединений и переподключение. Переподключение использует актуальные сохранённые параметры; форма явно показывает выбранный SSH-ключ, а Windows-обзор переключает на собственный файл. [Поведение и проверки](TAB_SESSION_ACTIONS.md).

Приёмка 0.9.1: готовый EXE — 24 GUI-сценария, Windows unit — 88 passed/1 skip; Astra — 145 unit и девять GUI-наборов. Новый DEB установлен, код сверён, новые действия и RDP повторно проверены. Старые файловые диалоги Windows отклоняются после смены поколения соединения и не перенаправляют запись на новый сервер.

Состояние на 24 октября 2026 года. Общий релиз — 0.9.1 для Astra Linux и Windows; номер/параметры находятся в `shared/product.json` и фактическая [матрица функций](FEATURES.md). Это план оставшейся работы, а не перечень доступных возможностей и не обещание сроков выпуска.

В 0.9.0 реализованы строка состояния SSH/local, единый менеджер SSH/RDP-профилей и clipping встроенного Windows RDP. Подтверждение hover-исправления — медленный ручной тест пользователя; формулы/формы проверяются отдельно. Расширенная приёмка разных DPI, GPU и нескольких мониторов остаётся задачей, как и мониторинг иных SSH-систем без Linux /proc. [Границы реализации](HOST_STATUS.md).

Релиз прошёл native build обеих ОС: 86 Windows tests + один privilege skip, 23 сценария готового EXE, 145 Python-тестов и восемь GTK-наборов. DEB установлен на Astra 1.6, проверены установленный код и реальный RDP. Медленный hover-тест Windows остаётся ручным; быстрые focus cycles не заменяют его. Контроль исходников, ASAR, native helper и CRC ZIP — в `dist/releases/0.9.0/artifact-verification.json`.

## MultiExec: текущее состояние

**Основной живой сценарий MultiExec реализован в 0.2.0.** Существующие терминалы разных хостов показываются рядом без повторного входа; получатели отмечаются галочками у панелей. Есть «Выбрать все», «Снять все», индикатор режима/числа получателей и `Ctrl+Shift+M`. Набор и управляющие клавиши из отмеченного VTE направляются другим отмеченным панелям; неотмеченная панель остаётся локальной. Новое или переподключённое соединение требует нового выбора.

Вставка CLIPBOARD/PRIMARY выполняется нативно в каждой панели с её кодировкой и bracketed paste. Макросы и программная отправка остаются локальными. В 0.2.1 старая нижняя строка «Команда / В отмеченные / Выполнить» удалена по просьбе пользователя; для группового ввода используются верхняя панель MultiExec и галочки получателей.

Если переподключение застало незавершённый нативный запрос вставки, новое соединение открывается в отдельной неотмеченной вкладке с тем же профилем. Старая панель становится доступной только для чтения истории; её процесс остаётся до закрытия. Так отложенный ответ буфера не переходит в новый PTY. Штатное переподключение без такого запроса выполняется в прежней панели.

Сложные асинхронные IME пока не поддерживаются. Приёмка на независимых внешних узлах и с интерактивными приложениями остаётся открытой. Ориентир — [официальная документация MobaXterm, раздел 1.3](https://mobaxterm.mobatek.net/documentation.html); наличие основного сценария не означает полного совпадения продуктов.

## P0 — ME-01: полноценный MultiExec

### Реализация

- [x] Отдельный переключатель MultiExec, явный индикатор включённого режима и количества получателей; при запуске режим выключен.
- [x] Выбор/исключение отдельных живых терминалов с показом имени подключения. Новые, завершённые и переподключённые соединения исключаются из прежней группы.
- [x] Общий вид существующих терминалов разных вкладок без нового входа; возврат исходных вкладок, разделений и фокуса. При разделении можно выбрать существующую панель или новый профиль другого хоста.
- [x] Передача байтов обычного ввода и управляющих клавиш VTE с защитой от рекурсии; отдельная нативная вставка для каждого получателя.
- [x] Обычная кириллица, смешанные UTF-8/CP1251, CLIPBOARD/PRIMARY и собственный bracketed paste каждой панели.
- [x] Приостановка режима и локальная работа с неотмеченным источником. Поля настроек, поиска и редактора вне VTE не являются источниками живого ввода.
- [x] Ввод непосредственно в отмеченных терминалах через живой MultiExec; на каждое нажатие подтверждение не показывается. Старая нижняя строка отправки удалена.
- [x] Изоляция незавершённой нативной вставки при переподключении: прежний VTE остаётся только для чтения, новое соединение получает отдельную неотмеченную панель.
- [ ] Поддержать сложные IME с асинхронной фиксацией текста вне события клавиатуры; определить и проверить взаимодействие с различающимися терминальными режимами интерактивных программ.

### Приёмка

- [x] На трёх локальных PTY выбрать два: текст и управляющие клавиши получают только выбранные, ровно по одному разу, без зацикливания и удвоения ввода в источнике. Также проверены выбор всех трёх и два отдельных SSH-соединения к одной ВМ.
- [x] Ввод в исключённой панели остаётся локальным. В 0.2.1 проверен обычный ввод в поле поиска подключений вне VTE; программная отправка и ответ терминала не рассылались.
- [x] Проверены русский/английский ввод, UTF-8/CP1251 в обе стороны, Enter, Backspace/Delete, Tab, навигация, Ctrl+C, NUL и CLIPBOARD/PRIMARY с собственным bracketed paste получателей.
- [x] Перемещение и разделение сохраняют процессы/историю; повторное включение общего вида восстанавливает раскладку и фокус. Новые, завершённые и переподключённые панели требуют нового выбора.
- [x] Проверены нативная вставка без `commit`, изоляция старого VTE при переподключении, сохранение его точной истории и процесса, запрет дальнейшего ввода и повторного использования PTY; панель истории закрывается штатно.
- [ ] Дополнительно проверить поля поиска/настроек, историю и дополнение в реальной оболочке, интерактивные `vim`/`top`, разрыв SSH во время ввода и независимые внешние серверы.
- [x] Правила маршрутизатора исключают RDP/VNC и панели SSH-туннелей; это проверено модульным тестом. Проверка самих внешних клиентов остаётся в QA-01.
- [x] Отключение режима прекращает рассылку: пройдены модульная проверка остановки во время маршрутизации и пауза в GUI/SSH.
- [ ] Дополнительно проверить отсутствие паролей и введённых данных в отладочных журналах всех путей ввода.
- [x] Есть 27 тестов маршрутизации и полная GUI-проверка на Astra Linux 1.6 с VTE 0.46; результаты записаны в документации.

Основные пункты реализации выше описывают код 0.2.1; отметки приёмки выставляются отдельно после завершённых проверок. `tests/smoke_multiexec.py` проверяет точные байты локальных PTY, исключение панелей, вставку, кодировки и сохранение процессов/истории при перемещении. `tests/smoke_multiexec_network.py` предназначен для двух реальных SSH-соединений с локальным сервером ВМ. Эти сценарии не заменяют проверку независимого внешнего кластера и `vim`/`top`.

### FS-01: файловая работа

- [ ] Загрузка/скачивание каталогов с явной политикой символьных ссылок, конфликтов, прав и незавершённых файлов.

- [x] Просмотр и изменение прав одного файла или каталога через SFTP, включая sudo на удалённом Linux.

### SSH-01: единые параметры соединения

- [x] Пользовательские профили ключей для прямого SSH: выбор из `~/.ssh`, основной профиль и явный выбор в подключении, локальные метаданные без passphrase. Добавочные идентичности и маршруты из OpenSSH выявляются и отклоняются; для них доступен системный режим.
- [x] Разблокировка ключа через ssh-agent для повторных SSH/SFTP-подключений без нового ввода passphrase, пока агент хранит ключ.
- [x] SFTP активного SSH-терминала: неинтерактивная попытка ключом/агентом, запрос учётных данных после ошибки аутентификации, ограниченный кэш соединений и каталогов.
- [x] Резервный OpenSSH для прямого SFTP при несовместимости серверного ключа или входа по ключу в Paramiko. Сохраняются выбранный файл/ключ агента, проверка `known_hosts` и обязательные SSH-маршруты.
- [ ] Расширить одинаковую обработку SSH-алиасов и настроек терминалом и файловой панелью: для прямого именованного профиля фактические сервер, пользователь и порт уже берутся из `ssh -G`, остальные политики ещё требуют унификации.
- [ ] Согласовать именованные профили с добавочными `IdentityFile`/`CertificateFile`, `HostKeyAlias`, `ProxyJump`/`ProxyCommand`; сохранить выбор ключа, политику доверия и обязательный маршрут без скрытого обхода.
- [ ] Отдельные ключи/параметры для каждого шлюза; совместимые с целевой системой современные форматы ключей, агент и интерактивная аутентификация.
- [ ] Объединить дополнительные параметры/методы аутентификации и исследовать переиспользование самого OpenSSH-транспорта; общий агент ключей не является общим транспортом.
- [ ] Проверить hashed known_hosts, нестандартные порты, смену ключа, IPv6 и разрешение имён через шлюз.

Приёмка: оба интерфейса подключаются к ожидаемому узлу по одному профилю, не обходят обязательный шлюз и не ослабляют проверку ключа; неподдерживаемый вариант даёт ясную ошибку.

### WS-01: рабочее пространство

Приёмка: перезапуск восстанавливает выбранные настройки, закрытие/восстановление не теряет данные; старые файлы версии 1 корректно открываются или мигрируются.
