# Короткий контекст для следующей правки

Это постоянная память проекта, не журнал чата. Достаточно прочитать этот файл и нужную строку карты ниже; исторические отчёты читать только при необходимости.

- Пользователь развивает **обе ОС одновременно**. По умолчанию функция/дизайн/общее исправление должны появиться в обеих реализациях; правило закреплено в `AGENTS.md` и `agent.md`.
- Одна версия релиза: `shared/product.json`. Генерация: `python tools/sync_shared.py`; контроль: `python tools/sync_shared.py --check`; новый номер: `--version X.Y.Z`.
- Общие JSON-сценарии: `shared/contracts/`; Python `tests/test_contracts.py`, JavaScript `windows/tests/contracts.test.cjs`. Сейчас проверяют валидацию/секреты, миграцию схемы 1, вложенное наследование и MultiExec/lifecycle.
- Жесты вкладок: `shared/contracts/tabs.json`, native `tests/smoke_tabs.py` / `windows/src/smoke-tabs.cjs`, `smoke-tab-management.cjs`. Генератор создаёт `tab-contracts.cjs`. Drop вкладки на вкладку объединяет; панель за заголовок → строка вкладок/«+» отделяет одну, объединённая вкладка → туда же разделяет все. ПКМ привязан к нажатой вкладке, bulk close подтверждается один раз; middle без вопроса. Linux `detach_pane_to_tab`, `separate_all`, `tab_action`; Windows `detachPane`, `separateAll`, `tabAction`. Не пересоздавать PTY/историю/выбор; GTK завершает DND до reparent и тестируется в собственном Xephyr.
- Сохранение вкладок хранит `workspace.json` в активном профиле. При отсутствии настройки оно включено, а явный выбор сохраняется. Linux `startup_tabs.py` / `_save_startup_tabs` / `_restore_startup_tabs`, Windows `backend/startup-tabs.cjs` / `saveOpenTabs` / `restoreOpenTabs`. Запись атомарна. Подтверждённый выход сохраняет раскладку до остановки соединений. Выход во время её восстановления оставляет прежний снимок. Сохранённые подключения записываются по ID, быстрые подключения проходят whitelist, процессы и история создаются заново. Linux `TerminalPane._ended_key` и Windows xterm key handler обрабатывают клавиши только после выхода. Иконки кнопок генерируются из `shared/icons.json`.
- Linux: `astraterm/`, Python **3.5.3**, GTK **3.22**, VTE **0.46**, OpenSSH, Astra SE **1.6**. Запуск `/usr/bin/python3.5`/`scripts/astraterm`, не системный переназначенный `python3`.
- Приёмка ВМ: `tools/verify_build_vm.py --password-prompt --host ... --user ... --fingerprint ...` запускать через native terminal/PTY. Дочерний Windows OpenSSH из runtime `node_repl` может сразу завершаться 255 без вывода; не ослаблять host-key/ACL ради этого и не тратить время на SSH-агент пользователя. Helper создаёт собственные ключи, loopback sshd и отдельный Xephyr/Xvfb, без изменения authorized_keys пользователя.
- Действия вкладки с 0.9.1: [TAB_SESSION_ACTIONS.md](TAB_SESSION_ACTIONS.md). ПКМ duplicate/reconnect охватывает всю нажатую вкладку; копии — новые соединения без записи/получателей. Reconnect получает свежую сохранённую сессию по ID и наследование группы, не старый runtime snapshot; протокол менять только новой вкладкой. Linux `reconnect_pane` готовит agent/vault и вызывает `restart(profile=...,ask=...)`, `restore_layout` восстанавливает дерево копии; Windows `prepareProfile/latestProfile`, `terminal:profile`, `duplicateId`. Выбор собственного файла в Windows переключает identity на system; именованный профиль блокирует поле и показывает фактический ключ. Кэш одного файла доступен под разными ID с независимыми PEM-буферами.
- Windows: `windows/`, Electron **45**, xterm **6**, node-pty **1.1**/настоящий ConPTY, ssh2 **1.17**. Сборка Node.js **22+**; для пользователя Node/Python не нужны. Есть PowerShell 7 и штатный 5.1.
- Терминал Windows открывается в `.terminal-viewport` без padding. Внешняя `.terminal-container` задаёт отступы. FitAddon измеряет родителя xterm, поэтому отступы родителя приводят к обрезанию последней строки и лишним колонкам. Сценарий `terminal_viewport` в `contracts/tabs.json` проверяется на Electron и GTK.
- Поставка Windows: мастер NSIS позволяет выбрать папку, обновление использует записанный в реестре путь. Setup распаковывает файлы один раз, portable EXE — при каждом запуске, ZIP распаковывается вручную. Оба EXE используют `%APPDATA%/AstraTerm`. В подписанном feed `releases.windows.installer` содержит Setup, верхние поля Windows обслуживают portable. NSIS кладёт маркер в `resources` для выбора обновления установленной копией.
- Рамка окна: Windows `.window-controls` закреплены справа через `margin-left: auto`, без сжатия и без переопределения в компактном breakpoint. Linux использует штатную рамку Fly (`get_titlebar() is None`); собственные кнопки поверх неё не добавлять.
- Встроенный Windows RDP требует отключить Chromium DirectComposition до создания окна (GPU остаётся включён). Одного HWND_TOP недостаточно; проверять реальное изображение и ввод на разблокированном рабочем столе, capturePage нативный HWND не снимает. Bounds должны прийти helper до connect. Не скрывать поверхность по document.hidden/blur. С 0.8.1 смена разрешения дедуплицируется и ждёт 300 мс после resize; focus/show/restore по-прежнему выполняют SetWindowPos/RedrawWindow для native HWND, без повторной сетевой перенастройки экрана. `RdpKeyboard.cs` передаёт Win-жесты в input HWND своего ActiveX только при реальном foreground/focus; освобождает модификаторы при уходе. Одни KeyboardHookMode/COM SendKeys не подтверждают работу Win: проверять удалённые Start/Run визуально. Linux запускает FreeRDP с +grab-keyboard; smoke проверяет реальный X11 grab внутри и освобождение вне RDP. RDP-тесты одного серверного пользователя выполнять последовательно.
- Отдельные окна с 0.8.0: `floating.py` перемещает существующее дерево виджетов через GTK reparent, оставляя workspace/PTY в главном реестре. Windows `floating-windows.cjs` разрешает только подготовленный same-site popup; renderer переносит исходный DOM и вызывает xterm.open после смены document. Главный renderer остаётся единственным IPC-клиентом/InputRouter. RDP-helper меняет HWND-родителя через stdin, без reconnect. Закрытие отдельного окна возвращает вкладку; закрытие вкладки завершает процесс. Перед split/merge вернуть затронутые окна. Native тесты — smoke_tabs и smoke-rdp; снимки RDP на Astra делать напрямую XGetImage через принадлежащее GTK соединение, GDK/Cairo capture может падать на foreign surface.

- Windows ActiveX: `Present()` вызывает OLE in-place `DoVerb(-5)` только после входа/показа; повторный refresh делает repaint без UI-активации. RdpControl сохраняет presentation при lost focus: AxHost выполняет UI-deactivate на lost focus, а parent HWND находится в другом процессе. Явный фокус отдельно использует UI verb -4; Present не захватывает фокус. `allowBackgroundInput=1` сохранён для Electron/helper. Native visibility=true и RedrawWindow не гарантируют картинку; GPU off и CalculateNativeWinOcclusion этот случай не исправляют. Общие Win-клавиши/число циклов: `shared/contracts/rdp.json.native_input`; probe `windows/tools/rdp-focus-probe.ps1`, Linux `tests/smoke_rdp.py`. Снимать baseline до клика, 24 кадра blur/restore и Win вне RDP; проверять также exit code приложения.
- С 0.9.0 Windows native RDP: `ClipNativeSurface()` включает WS_CLIPCHILDREN у Electron owner и WS_CLIPSIBLINGS у RDP/Chromium siblings, в том числе после reparent. Без этого hover-перерисовка браузера закрашивала RDP, хотя все HWND были visible/frontmost. WM_SETCURSOR не передаётся из helper обратно в Chromium (CSS cursor hand). Медленный ручной тест: Пуск хоста → плавно внутрь RDP/обратно; автоматический focus probe его не заменяет. Пользователь подтвердил отсутствие почернения после clipping.
- Статистика и общий менеджер с 0.9.0: [HOST_STATUS.md](HOST_STATUS.md). Linux `host_stats.py`/`host_stats_ui.py`, Windows `backend/host-stats.cjs`/`.ps1`, `renderer/host-stats.js`; только SSH Linux и локальная машина, без shell input/auth prompts. Проверять generation/endpoint; Windows отдельный SFTP channel, Linux общая IO-блокировка файлов. Учётные данные: единый UI ключей/SSH/RDP паролей, необязательный зашифрованный protocol (legacy=both), ID/agent/формат envelope сохраняются.
- Shutdown Windows ожидает ConPTY output workers (включая уже закрытые вкладки) через TerminalManager.cleanupWaits/dispose, main finish ждёт их вместе с recording. Обычный node-pty drain 1 с, ограничение 3 с до завершения своего worker; немедленный app.exit до drain мог давать native fail-fast. Не заменять ожидание сигналом по старому PID.

- Общая JSON-схема **2**; секреты не входят. Linux: XDG `astraterm/sessions.json`; Windows: `%APPDATA%/AstraTerm/sessions.json`. Пути ключей между ОС не преобразуются.
- Импорт/пароли с 0.6.0: `importers.py`, `import_dialogs.py`, `vault.py`; Windows `backend/importers.cjs`, `vault.cjs`, main `prepareImport/applyImport/ensureVault`, renderer `importDialog/vaultDialog`. Форматы/границы — `docs/IMPORTS.md`; общие `contracts/imports.json`, `vault.json`. CredentialProfile отделён от профиля ключа: только ID/label в сессии, пароль в `credentials.vault.json` под мастер-паролем. Общий AES-GCM/PBKDF2 envelope задаёт `product.vault_parameters`; новые nonce, atomic/revision/lock, секреты не в preview/экспорте/argv/env. Native `smoke_imports.py`/`smoke-imports.cjs` проверяют настоящий SSH/SFTP и UI, только синтетические пароли. Linux `credential_launch.py` + частный askpass обеспечивают OpenSSH 7.4 и завершение SSH-ребёнка.
- SSH с несколькими факторами: Windows `TerminalManager._connectSSH` учитывает `partialSuccess` и ответы каждого раунда `keyboard-interactive`. GTK `CredentialController.answer_prompt` разрешает одно автоматическое использование пароля для точного запроса аккаунта и передаёт остальные запросы в диалог. Имя пользователя при пустом поле запрашивается до входа, код второго фактора не кэшируется. Общая проверка `contracts/ssh-interactive.json` выполняется в `terminal.test.cjs` и `smoke_imports.py`.
- Перенос `MobaXterm.ini` в Windows: меню «Файл → Пароли из MobaXterm», main `prepareMobaImport/applyMobaImport`, `backend/mobaxterm.cjs` и упакованный отдельно DPAPI worker. Приёмка на синтетическом DPAPI-файле в `smoke-imports.cjs`. CLI `tools/import_mobaxterm.py` и `astraterm/moba_migration.py` используют те же ID, формат и файлы блокировок. Порядок переноса описан в `docs/IMPORTS.md`.
- Пути SSH-ключей MobaXterm в Windows: `moba-key-path.cjs` раскрывает `_MyDocuments_` через `app.getPath('documents')` в `parseImport` и `IdentityManager.ensure`. В тестах каталог синтетический. `_CurrentDrive_` требует явного выбора файла, Linux хранит исходный путь с предупреждением.
- Управление мастер-паролем с 0.10.3: `CredentialManager.master_password` / `masterPasswordDialog`, операции `change_master` / `changeMaster` и `reset_master` / `resetMaster`. Смена проверяет текущий пароль даже после разблокировки. Сброс создаёт пустой зашифрованный файл с новой солью. Обе операции используют прежний envelope и атомарную запись под ревизией, без изменения сессий. Общие тестовые данные в `contracts/vault.json`, GUI-проверки в `smoke_imports.py` и `smoke-imports.cjs`.
- Перенос профиля через зашифрованный `.astraterm-backup` описан в [BACKUP.md](BACKUP.md). См. `backup.py` / `backend/backup.cjs`, `backup_dialogs.py` / `backup-ui.cjs`, `contracts/backup.json`. Файл содержит указанные SSH-ключи, вложенное зашифрованное хранилище с прежним мастер-паролем и сохранённые настройки. `active-profile.json` выбирает полностью подготовленный профиль на следующем запуске.
- Именованный ключ: в Linux ssh-agent; в Windows выбранный уже загруженный ключ агента, иначе кэш только до выхода из приложения. Windows не запускает службу и не вызывает `ssh-add` автоматически.
- SFTP следует **активному хосту**, независимо от `cd`/`su`/`sudo`. Linux использует отдельный кэш Paramiko/OpenSSH. Для прямых соединений OpenSSH повторяет согласование несовместимого серверного ключа или вход publickey с тем же файлом/агентом. Windows открывает SFTP через SSH-клиент терминала. Операция сохраняет исходный endpoint, generation и revision после `await`/callback.
- Прогресс загрузки в SFTP-панели приходит из callback `put` в GTK и `fastPut.step` в Electron. 100% только после атомарной публикации файла. `appearance.json` хранит тему, цвета по темам и видимость боковых панелей. Поля проверяют `appearance.py` и `backend/appearance.cjs`. Изменение палитры обновляет живые GTK/VTE и Chromium/xterm.js, включая отдельные окна.
- Выгрузка жестом с 0.10.5: Windows `bindSftpDrag` → `backend/sftp-drag.cjs` → `webContents.startDrag`, Linux `FileBrowser._drag_motion` → GTK `text/uri-list`. Временный файл готовится целиком в частном каталоге и привязан к исходному SFTP-поколению. Отпущенную до готовности кнопку заменяет повторный жест. Права и даты — `file_metadata.py` / `backend/file-metadata.cjs`, contract `file-metadata.json`. Время создания запрашивается дополнительным ограниченным SSH-каналом с фиксированным GNU stat и путём через stdin. SFTP v3 сам передаёт права и время изменения. Если сервер или ФС не предоставляют birth time, колонка показывает «—».
- Свёрнутые папки сохраняются по ID в отдельном `sidebar.json` рядом с `sessions.json`. Поиск временно раскрывает результаты. Цветные значки локальной ОС и RDP находятся в `ui_helpers.platform_pixbuf` и `renderer/app.js`.
- Кнопки боковых панелей и пункты меню «Вид» вызывают `toggle_sidebar/toggle_files` в GTK и `togglePanel` в Electron. При скрытии освобождается ширина рабочей области, SFTP и терминалы остаются подключёнными. Общий сценарий `side_panels` в `contracts/tabs.json` выполняют `smoke_design.py` и `smoke.cjs`. Значок Linux применяется к SSH в списке подключений.
- SFTP-сортировка: заголовки вызывают `file_sort.sort_rows` / `file-sort.js`, даты и размер сравниваются по исходным числам, каталоги всегда первые, отсутствующие значения последние. Контракт `file-sort.json`. Windows UI обслуживает внутренний `astraterm://app` с точным списком упакованных ресурсов (`local-ui.cjs`), главный frame проверяется в `assertAppSender`. Диагностический журнал в настройках выключен по умолчанию, сохраняет фиксированные коды событий в `astraterm.log` и хранит одну резервную копию по 1 МиБ.
- Перетаскивание файлов: `shared/contracts/file-drops.json`, GUI в `smoke_auth_profiles.py` и `smoke.cjs`. SSH-терминал берёт путь из OSC 7 или заголовка Bash. Файловая панель берёт путь из своего каталога. Разбор и проверка `terminal_directory.py` / `backend/terminal-directory.cjs`. Путь и поколение фиксируются при сбросе, до 100 обычных файлов идут через SFTP. Linux `app._upload_to_pane` → `files.upload_paths`. Windows `bindFileDrop` → `preload.uploadDropped` с путями из `webUtils` → `main.uploadFiles`. Сброс в SSH подавляет штатную вставку.
- MultiExec: новые/переподключённые/завершённые панели не включаются автоматически; неотмеченный источник локален; ответы терминала, макросы, фокус/mouse reports и формы не рассылаются. Linux source уже получил байты VTE, Windows router включает source сам.
- `node-pty` требует освобождать принадлежащий ему output worker; не сигналить завершённому PID. PSReadLine-алиасы Ctrl для раскладок действуют только в дочернем PowerShell.
- Не обещать полный MobaXterm/полный паритет: Windows пока без X11/Mosh/Telnet/Serial/VNC; RDP с 0.7.0 встроен: `rdp.py`/`rdp_launch.py`, Windows `backend/rdp.cjs`/`native/RdpHost.cs`, renderer `addRdpPane/syncRdpBounds`; правила и приёмка — `RDP.md`. Только FreeRDP 2.11 проверен, без gateway/split/VNC; никогда не включать в MultiExec. Сложные IME и расширенная приёмка интерактивных программ остаются в плане.

## Где менять

- SFTP **Права…**: GTK `files._chmod` / `file_permissions.py`, Electron `editFilePermissions` / `backend/file-permissions.cjs`. Обычный режим использует SFTP chmod. Sudo открывает exec-канал того же SSH-транспорта, выполняет фиксированный `shared/sftp-chmod.py`, отправляет пароль только в stdin при запросе. Помощник проверяет ревизию и меняет права по дескриптору без перехода через ссылки. Контракт `shared/contracts/file-permissions.json`.

- Ключ `-Version` всех трёх build scripts передаётся в `tools/build.py --version` и перед сборкой обновляет общий product через `sync_shared.set_version/synchronize`. `-Plan` сохраняет файлы. Публикация сайта и релиза включается `-Deploy`. Описание всех параметров — `Get-Help ./build-all.ps1 -Full`, сценарии — `docs/BUILD.md`.

- Сайт/обновления с 0.10.0: [UPDATES.md](UPDATES.md). Основной пользовательский шаблон — `website/production/`, сборщик — `tools/website_build.py`; три концепции сохранены под `/alternatives/`. `tools/release.py` подписывает RSA-PSS список релизов и публикует проверенные native-артефакты по FTPS через `-Deploy` трёх build scripts. Подпись/HTTPS/размер/SHA-256 обязательны; URL/команды не принимать от renderer. Python `updates.py`/`update_ui.py`, Windows `backend/updates.cjs`/`update-ui.cjs`/`update-install.ps1`. Приватный ключ — вне checkout/хостинга, в product только публичный; доступы не хранить. Windows заменяет portable EXE после выхода с `.previous`; Linux — проверенный DEB через системный установщик и явный перезапуск.

- Статистика сайта: `website/production/admin/`, PHP и журналы доступа REG.RU. `tests/site_statistics.php` проверяет подсчёт. При потере локального пароля `tools/site_admin_reset.py` заменяет хеш через FTPS вне webroot. Вход и правила подсчёта описаны в `website/production/README.md`.

## Проверки и чтение

- Быстро: `python tools/sync_shared.py --check`; `python -m unittest discover -s tests -p test_contracts.py`; `node --test windows/tests/contracts.test.cjs`.
- Linux: `/usr/bin/python3.5 -m unittest discover -s tests -p 'test_*.py'`; GTK/PTY — соответствующий `smoke_*.py` на Astra. GUI Windows не доказывает работу Linux.
- Windows: из `windows/` — `npm test`; GUI — `npm run smoke`; готовый EXE — `--smoke-test`, `ASTRA_SMOKE_OUTPUT` задаёт каталог отчёта. Не использовать обычные данные пользователя для тестов.
- Сборка: [BUILD.md](BUILD.md). Сценарии изменений: [DEVELOPMENT.md](DEVELOPMENT.md). Решения/границы: [ARCHITECTURE.md](ARCHITECTURE.md). Тонкости механизма: [ENGINEERING_RULES.md](ENGINEERING_RULES.md).
- Актуальные функции/различия: [PLATFORM_PARITY.md](PLATFORM_PARITY.md), [FEATURES.md](FEATURES.md). Запланированное: [ROADMAP.md](ROADMAP.md). Новые отчёты сборки лежат в `dist/releases/<version>/*/build.json`, не заменяют предыдущую историю проверок.

Разработка и тесты используют конфигурацию из окружения/SSH-agent. Реальные адреса и секреты в эту память не добавлять.
