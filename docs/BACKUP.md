# Перенос профиля AstraTerm

В Windows и Astra Linux откройте **Файл → Создать резервную копию…**, выберите новый файл `.astraterm-backup` и задайте пароль копии. На втором компьютере откройте **Файл → Восстановить из резервной копии…**, выберите этот файл, введите его пароль и подтвердите восстановление. Перезапустите AstraTerm для загрузки восстановленного профиля.

Копия содержит подключения и папки с наследуемыми SSH-настройками, макросы, туннели, профили ключей, учётные данные SSH/RDP, состояние свёрнутых папок и настройки диагностического журнала. Подтверждённые ключи серверов из встроенного хранилища доверия Windows переносятся в копии. Astra Linux продолжает использовать системный OpenSSH и его `known_hosts`.

Файлы приватных ключей берутся из сохранённых подключений, групп, туннелей и профилей ключей. При наличии копируются `.pub` и `-cert.pub`. Для недоступных файлов программа показывает список и предлагает сохранить оставшиеся данные. Профили, ID и ссылки сохраняются, а пути к скопированным файлам заменяются на локальные на принимающем компьютере. Passphrase ключа остаётся прежней. Ключи из ssh-agent, токенов и системных настроек SSH без явной ссылки из AstraTerm переносятся средствами соответствующей системы. Открытые вкладки, история терминалов, записи вывода, кэш и системная папка `~/.ssh` находятся вне профиля.

Пароль резервной копии открывает файл `.astraterm-backup`. Перенесённое хранилище учётных данных открывается прежним мастер-паролем с исходного компьютера. При восстановлении AstraTerm подготавливает новый профиль целиком и выбирает его на следующий запуск. Данные предыдущего профиля остаются в прежнем каталоге. Обычный **Экспорт подключений** создаёт JSON с метаданными подключений.

## Формат и реализация

Параметры версии и размеров заданы в `shared/product.json`. Контейнер использует AES-256-GCM с 128-битным тегом, случайной 96-битной nonce и ключом от PBKDF2-HMAC-SHA256 с отдельной 256-битной солью и 600 000 итераций. AAD `AstraTerm profile backup v1` отделяет формат копии от хранилища паролей. Зашифрованный файл хранилища переносится внутри контейнера с прежними параметрами шифрования. [AES-GCM, NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final).

Linux использует `backup.py` и `backup_dialogs.py`, Windows — `backend/backup.cjs` и `backup-ui.cjs`. Код проверяет допустимые документы, размеры, идентификаторы и ссылки. Имена восстановленных файлов определяет программа. Она записывает профиль в новый защищённый каталог под `restored-profiles`, затем атомарно переключает `active-profile.json`. При сбое до переключения остаётся активен прежний профиль. Проверка активного каталога защищает от повторного восстановления из уже устаревшего экземпляра приложения. Права ключей на Linux `0600` в каталоге `0700`. На Windows каталог использует ACL текущей учётной записи.

Общие данные проверок находятся в `shared/contracts/backup.json`. Тесты открывают восстановленный OpenSSH-ключ с прежней passphrase и хранилище с исходным мастер-паролем. Проверяются неверный пароль, повреждённый тег, сохранность существующего файла копии и сохранение предыдущего профиля при конфликте.
