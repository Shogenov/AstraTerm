# RDP внутри AstraTerm

Начиная с 0.7.0 RDP открывается в отдельной вкладке приложения в обеих ОС. Закрытие вкладки отключает клиент; оно не выполняет выход пользователя на удалённой машине. Переподключение находится в меню «Инструменты». Обычные вкладки терминалов продолжают работать независимо.

Windows использует штатный Microsoft RDP ActiveX в собственном дочернем HWND, а не процесс `mstsc.exe`. Linux использует FreeRDP 2.x/X11 с `/parent-window` внутри GTK Socket. На Astra требуется пакет `freerdp2-x11`; протестирована версия 2.11.7. Совместимость с FreeRDP 3 пока отдельно не подтверждена. Electron не переносится в Astra.

С 0.8.0 вкладку RDP можно извлечь в отдельное окно и вернуть без переподключения; крестик этого окна возвращает вкладку. [Отдельные окна](FLOATING_WINDOWS.md). Chromium occlusion не скрывает нативную поверхность. С 0.8.1 возврат фокуса не вызывает повторную смену разрешения: оно обновляется только при изменении размера, после паузы 300 мс. Нативный SetWindowPos/WM_WINDOWPOSCHANGED для восстановления HWND и z-order сохраняется даже при одинаковых bounds. Не путать восстановление HWND с сетевой перенастройкой удалённого экрана.

Клавиши Win слева/справа и их сочетания направляются в удалённый рабочий стол, пока он получает ввод. В Linux включён штатный `+grab-keyboard` FreeRDP; захват освобождается при выходе указателя/фокуса из RDP, штатная правая Ctrl также освобождает клавиатуру. В Windows `KeyboardHookMode=1` одного недостаточно при родителе из другого процесса: `RdpKeyboard.cs` перехватывает только Win-жесты при фактическом фокусе на своём ActiveX и отправляет WM_KEY/WM_SYSKEY непосредственно его input HWND. Фокус проверяется по foreground owner и GetGUIThreadInfo, не по последней выбранной вкладке. Остальной ввод проходит штатно; blur/hide/reparent/close освобождают удалённые модификаторы. Ввод не журналируется, renderer его не получает. Вне RDP системные клавиши работают локально.

С 0.9.0 `ClipNativeSurface()` исключает дочерние HWND из отрисовки родителя (WS_CLIPCHILDREN) и запрещает Chromium siblings закрашивать соседний RDP (WS_CLIPSIBLINGS). Одного HWND_TOP недостаточно: ошибка проявлялась при hover, хотя геометрия/visibility/z-order были корректны. Повторить clipping после reparent. Основание механизма — [документация Microsoft о clipping дочерних окон](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#clipping).

RdpControl сохраняет presentation при потере фокуса. `Present()`/DoVerb(-5) вызывается после входа/показа, обычный refresh только перерисовывает поверхность. Явный фокус использует DoVerb(-4), WM_SETCURSOR не наследует CSS-курсор Chromium, WM_MOUSEACTIVATE не активирует его render child. Сохранены allowBackgroundInput=1 и реальная проверка input HWND в RdpKeyboard. DirectComposition отключён до первого BrowserWindow, GPU сохранён.

Завершение Windows ожидает принадлежащие ConPTY output workers, включая уже закрытые вкладки: штатный drain занимает около секунды; через 3 секунды завершается только оставшийся собственный worker. Не выполнять немедленный Electron app.exit во время этого drain: тест выявил периодический native fail-fast при завершении процесса. Проверка жизненного цикла есть в `terminal.test.cjs`; Linux VTE этим механизмом не затронут.

Размер области следует окну приложения. Windows поддерживает SmartSizing и обновление размера удалённого экрана; Linux отправляет изменения через dynamic-resolution. Работают клавиатура, мышь и перенаправление буфера обмена. Нативные RDP-панели исключены из MultiExec и терминального общего вида; объединение их с SSH через перетаскивание пока не поддерживается. После переключения вкладки соединение сохраняется, а удалённая поверхность скрывается. HTML-диалоги Windows также скрывают её на время ввода.

Пользователь и домен задаются в подключении; если пользователь не указан, клиент запрашивает его. Профиль импортированного пароля переиспользуется из разблокированного мастер-хранилища. Без профиля пароль запрашивается для подключения. Пароль не сохраняется в сессии, аргументах, переменных окружения или журналах: Windows получает его через частный stdin собственного помощника, Linux — через отдельный PTY с выключенным echo. Ограничение общего сценария: пароль без NUL/переводов строк, до 511 байт UTF-8. Профили ключей SSH для RDP не используются.

Проверка сертификатов сохранена. Microsoft показывает штатное предупреждение; FreeRDP показывает детали и отпечаток в диалоге AstraTerm. Доверие неизвестному сертификату требует решения пользователя. Linux предлагает доверять только текущему подключению. Автоматических `/cert:ignore`, TOFU и отключения проверки нет. Для штатной работы без предупреждений используйте сертификат доверенного центра с подходящим именем сервера.

Сейчас не реализованы RD Gateway, SSH-шлюз для RDP, настройки перенаправления дисков/принтеров, RDP внутри split и встроенный VNC. Обязательный `jump_host` отклоняется, а не заменяется прямым подключением. Диски и принтеры по умолчанию не перенаправляются.

## Код и сборка

- `astraterm/rdp.py`: GTK-панель, проверяемые XCB-запросы, запросы пароля/сертификата и жизненный цикл. `rdp_launch.py` создаёт controlling TTY только для дочернего FreeRDP.
- `windows/native/RdpHost.cs`, `RdpKeyboard.cs`: .NET Framework/WinForms/AxHost-помощник с Microsoft COM-компонентом и ограниченным мостом Win-клавиш. `windows/tools/build-native.cjs` компилирует native/*.cs в x64 EXE штатным .NET Framework 4 compiler. npm prestart/presmoke/predist включают сборку; пользователю компилятор не нужен.
- `windows/src/backend/rdp.cjs`: владелец процессов, поколений, частных каналов и ограниченных координат. IPC renderer знает только ID/метаданные и область отображения, никогда пароль из хранилища. Нативный EXE доставляется через `asarUnpack`.
- `addRdpPane`/`syncRdpBounds` в renderer управляют вкладкой и видимостью; RDP не регистрируется в InputRouter. `TerminalWorkspace` выбирает RdpPane отдельно от TerminalPane.
- С 0.7.1 Windows main отключает DirectComposition до создания окна, сохраняя GPU: иначе Chromium закрывает нативное изображение после успешной аутентификации. Backend передаёт bounds до connect; helper возвращает фактическую геометрию HWND для проверки.
- `shared/contracts/rdp.json`, Python contracts и `windows/tests/rdp.test.cjs`: метаданные, отсутствие секретов, отмена ожидающей аутентификации, устаревшие события, bounds и закрытие.

## Приёмка

Проверки действительного RDP сервера запускаются отдельно и явно: `tests/smoke_rdp.py` получает JSON `{host, username, password}` через stdin; Windows `--rdp-test` читает `ASTRA_RDP_TEST_HOST`, `ASTRA_RDP_TEST_USER`, `ASTRA_RDP_TEST_PASSWORD` только как тестовую конфигурацию и удаляет их до запуска помощника. Настройки тестов изолированы. Обычный `-Smoke` не подключается к пользовательским RDP-серверам. Скриншоты нативного Windows HWND нужно снимать на рабочем столе: Chromium capturePage их не содержит.

Проверка ввода открывает удалённое окно «Выполнить» или поиск Windows, вводит контрольную строку с клавиатуры/через буфер обмена и закрывает его без запуска команды. Отчёты и изображения разработчика: `artifacts/rdp/`; адреса, логины и секреты не включаются в документы проекта и выпуск.

Общий контракт ввода: Win открывает именно удалённый «Пуск»; Win+R — удалённое «Выполнить»; после ухода из RDP Win снова локальна; возврат/отдельное окно/вкладка не оставляют зажатых модификаторов. Проверять фактические снимки обоих меню. S_OK от COM SendKeys или сохранение foreground HWND сами по себе не подтверждают доставку: на проверенном Windows SendKeys мог завершаться успешно без видимого действия. Linux smoke дополнительно проверяет реальный X11 keyboard grab через независимое соединение: внутри захват занят, после перехода к GTK снова свободен. Пустой Xephyr без такой проверки пропускает регрессию `-grab-keyboard`.

Для Windows выполнять повторные blur/restore с другим нативным процессом и снимать изображение до щелчка по RDP, включая первые кадры после возврата. Счётчик обновлений разрешения не должен расти при неизменной геометрии. Проверить также minimize/restore, modal, вкладки, resize и отдельное окно. RDP-тесты одного серверного пользователя запускать последовательно: второй клиент Windows 11 отключает первый.

`windows/tools/rdp-focus-probe.ps1` — собственный нативный тестовый процесс: принимает HWND/PID, проверяет hit target, снимки 12 циклов blur/restore, удалённые левую/правую Win и Win+R, локальную Win вне RDP. Запускается на разблокированном рабочем столе параллельно `--rdp-test`; этап/свои HWND берутся из `ASTRA_SMOKE_OUTPUT/progress.json`, завершение этапов отмечается `background.done`, `capture.done`, `floating.done`. Подтверждение сертификата тестового сервера требует явных `-AcceptCertificate -ExpectedCertificateName`; адреса/пароли ему не передаются. Само наличие файлов снимков не заменяет визуальную проверку Start/Run.

Этап `baseline` снимает первое изображение без захвата фокуса RDP и без клика; `baseline.done` продолжает тест. Проверять также exit code самого portable процесса: JSON `PASS` перед нештатным завершением не считается успешной приёмкой.

Приёмка 0.8.1: установленный DEB на Astra и готовый portable EXE подключались к настоящему Windows RDP. В обеих ОС визуально подтверждены удалённый «Пуск» по левой/правой Win и «Выполнить» по Win+R с контрольной строкой через clipboard; вне RDP клавиатура освобождается. Windows дополнительно прошёл baseline без клика, 12 внешних blur/restore (24 кадра без чёрной поверхности), неизменность счётчика display updates по focus, minimize/restore, modal, resize, floating/dock, reconnect и закрытие helper. Portable процесс завершился с кодом 0; его SHA-256 привязан к отчёту. Общая проверка — 141 Linux unit, семь native GUI-наборов, 81 Windows unit passed/один privilege skip и packaged GUI smoke. Отчёты и хеши изображений: `dist/releases/0.8.1/<platform>/validation/rdp.json`.

Приёмка 0.8.0 добавляла отдельное окно и возврат без смены процесса/поколения (в Linux также сохраняются оба XID), native close этого окна, Windows blur/focus и minimize/restore. Перенос Windows завершается подтверждением нового родителя helper до уничтожения старого окна. Визуальные свидетельства и хеши снимков записаны в `dist/releases/0.8.0/<platform>/validation/rdp.json`; расширенная проверка 0.8.1 выявила необходимость явной OLE-активации. GUI терминалов проверяет ввод из отдельного окна только в отмеченные получатели MultiExec.

Приёмка 0.7.1: общий native build прошёл 141 Python-тест, 77 Windows-тестов (один privilege skip), семь Linux GUI-наборов и 20 проверок packaged Windows EXE. В готовом Windows EXE визуально подтверждены рабочий стол внутри вкладки, мышь, вставка контрольной строки и её дополнение обычными клавишами. Проверены фактическая геометрия HWND, resize, смена вкладок, скрытие под HTML-диалогами, reconnect и завершение helper. На установленном DEB Astra подтверждены настоящий рабочий стол, ввод/clipboard, resize, смена вкладок, reconnect и освобождение клиента. Отчёты выпуска: `dist/releases/0.7.1/windows/validation/rdp.json`, `linux/validation/rdp.json` внутри того же каталога релиза. Сертификат тестового сервера принят явно на время проверки; автоматическое доверие в приложение не добавлено.

Основания реализации: [Microsoft RDP ActiveX](https://learn.microsoft.com/en-us/windows/win32/termserv/remote-desktop-activex-control-classes), [обработка полноэкранного режима контейнером](https://learn.microsoft.com/en-us/windows/win32/termserv/imstscadvancedsettings-containerhandledfullscreen), [исходники FreeRDP 2.11.7](https://github.com/FreeRDP/FreeRDP/tree/2.11.7/client).


Приёмка 0.9.0: пользователь медленно нажал Пуск хоста и перевёл мышь в/из встроенной области. После курсорной изоляции почернение ещё оставалось; после clipping пользователь подтвердил, что картинка больше не чернеет. Это ручная проверка на его Windows 11, а не результат быстрого автоматического focus probe. Предыдущие 24 focus-кадра 0.8.1 не покрывали hover и не доказывали устранение этой ошибки. Для нового теста: --rdp-test, ASTRA_RDP_MANUAL=1, изолированный vault, сертификат подтверждается человеком; manual.done завершает только принадлежащий тесту клиент.
