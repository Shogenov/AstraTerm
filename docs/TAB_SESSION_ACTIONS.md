# Дублирование и переподключение вкладки

С 0.9.1 контекстное меню вкладки обеих ОС содержит «Дублировать вкладку» и «Переподключиться». Действие привязано к вкладке, по которой нажали ПКМ, включая неактивную или вынесенную в отдельное окно.

Дублирование создаёт новые соединения для всех панелей выбранной вкладки. Сохраняются порядок и разделение; исходные процессы и история остаются на месте. Копия появляется в главном окне, её получатели MultiExec выключены. История и файл записи исходного процесса не копируются. Как при обычном открытии, выполняется настроенная команда после входа. Сохранённая сессия в списке не размножается.

Переподключение перезапускает все панели выбранной вкладки; остальные вкладки сохраняют свои процессы и соединения. Перед остановкой работающей вкладки запрашивается одно подтверждение. История эмулятора остаётся, выбор MultiExec сбрасывается. Windows сохраняет прежнее поведение остановки записи; Linux продолжает существующую запись с добавлением, без усечения файла. Задержанная нативная вставка VTE по-прежнему изолирует прежнюю панель и открывает новое соединение отдельно.

Оба действия и обычное переподключение берут актуальные сохранённые настройки по ID сессии и заново применяют наследование группы и выбор учётных данных. При удалённой из списка сессии используются параметры открытой панели. Изменение протокола требует открытия новой вкладки: существующий VTE/xterm/RDP-виджет не превращается в другой клиент. Новое SSH-соединение проверяет серверный ключ; подтверждения доверия не обходятся.

Файловый редактор и отложенные диалоги остаются привязаны к прежнему соединению. Windows передаёт generation, зафиксированный до открытия диалога/чтения файла; backend отклоняет его после reconnect, даже если terminal ID и путь совпали. Linux использует прежние проверки исходного SFTP/generation. Исправление настроек не должно перенаправлять старое сохранение на другую машину.

## Выбор ключа после импорта

Именованный профиль SSH-ключа имеет приоритет над сохранённым полем собственного файла. В обеих формах показывается фактически выбранный путь; поле собственного ключа недоступно при активном именованном профиле. В Windows кнопка «Обзор» явно переключает на выбранный собственный файл. Если ключ задан группой, сначала нужно изменить её настройки или выключить наследование для этой сессии.

Windows повторно использует уже разблокированный файл при переключении между его именованным профилем и собственным путём. Кэш остаётся только в памяти; буферы разных записей независимы и очищаются отдельно. Другие файлы и посторонние ключи агента не подставляются. При отказе сервера сообщение называет пользователя/хост и способ аутентификации; оно не доказывает, что ключ разрешён сервером для этого пользователя.

## Карта изменений и проверки

- Linux: `app.py:tab_action`, `_latest_pane_profile`, `reconnect_pane`; `TerminalWorkspace.restore_layout`, `TerminalPane.restart`, `RdpPane.restart`; форма `dialogs.py`.
- Windows: `main.cjs:prepareProfile/latestProfile`, IPC `session:open` с `duplicateId`, `terminal:reconnect`; `terminal:profile` обновляет renderer; `renderer/app.js:tabAction/sessionDialog`; `IdentityManager.ensure` переиспользует разблокированный файл.
- Общие правила/надписи — `shared/contracts/tabs.json`; генерация через `sync_shared.py`.
- GTK: `smoke_session_actions.py` проверяет дерево разделений, разные PTY/PID, исходную историю и состав получателей, область переподключения и свежие параметры. `smoke_auth_profiles.py` проверяет реальный SSH: сохранённый неверный порт, исправление, повторное подключение без новой passphrase.
- Windows: `smoke-session-actions.cjs` проверяет реальный отказ/успех SSH после изменения сессии и выбора файла в форме; `smoke-tab-management.cjs` — копию объединённой вкладки; `identities.test.cjs` — переиспользование файла и независимое очищение буферов. Все тестовые ключи синтетические.
