# Сайт, публикация и обновления

Один публичный источник — `https://astraterminal.ru`. Домашняя страница строится из пользовательского `website/production/template.html`, скриншоты — настоящие приложения с изолированными тестовыми данными. Исходный файл шаблона сохранён. Три прежние концепции остаются в `website/design-previews/` и публикуются под `/alternatives/`. Сборщик сайта — `tools/website_build.py`; отдельная база данных не нужна.

## Общий контракт обновления

`shared/product.json.update_parameters` задаёт HTTPS origin, `/releases/latest.json`, встроенный публичный RSA-ключ и ограничения размеров. `tools/sync_shared.py` зеркалирует их в Python и Node. Сценарии — `shared/contracts/updates.json` с синтетическим публичным ключом и подписями; тестовый приватный ключ не сохраняется.

`latest.json` содержит ровно используемые поля `payload` и `signature`: base64 от точных байтов UTF-8 JSON и RSA-PSS/SHA-256 с MGF1/SHA-256, salt length 32. Сначала проверяется подпись, затем схема 1/product, числовая версия major.minor.patch, точное официальное имя файла, размер и SHA-256. Поддерживаются самостоятельные версии Windows/Linux в одном подписанном списке. Старшая установленная версия не понижается; prerelease не участвуют в stable-канале. Обычный `downloads.json` предназначен для посетителя сайта и не используется приложением для принятия решения об установке.

Скачивание: только HTTPS с системной проверкой сертификата, точный origin/путь, без redirects, ограничение списка 128 КиБ и пакета 512 МиБ. Сначала частный новый временный файл; только после точного размера и SHA-256 он становится доступен установщику. Ошибка/обрезанный файл удаляются. Renderer не передаёт URL, имя файла или команду установки через IPC.

Запись Windows хранит portable EXE в полях `url`, `bytes` и `sha256`. Дополнительный объект `installer` с теми же полями содержит NSIS Setup для установленной копии. Установщик и portable входят в одну подпись, имя обоих файлов привязано к версии. Старые клиенты продолжают читать верхние поля Windows.

## Интерфейс и ОС

На обеих ОС: меню **Справка → Проверить обновления…** и одна фоновая проверка через 15 секунд после запуска. Сетевые ошибки фоновой проверки не показывают диалог; ручная проверка сообщает результат. Скачивание и установка требуют действий пользователя. Ошибки обновлений не мешают терминалам.

После нажатия «Скачать» полоса показывает долю записанных байтов от размера в подписанном списке. На 100 % интерфейс сообщает о проверке пакета. Запуск установщика предлагается после проверки и требует отдельного подтверждения.

- Windows: `backend/updates.cjs` проверяет подпись и скачивает пакет, `update-ui.cjs` управляет диалогами. `update-launch.ps1` запускает `update-install.ps1` через Windows. Помощник повторно проверяет размер и SHA-256, подтверждает готовность и ждёт разрешения и выхода AstraTerm. При сбое запуска приложение остаётся открытым. Для копии с маркером NSIS в `resources` открывается окно Setup. ZIP может перейти на Setup, если он есть в списке релизов. Portable определяется по `PORTABLE_EXECUTABLE_FILE` и обновляется заменой EXE с резервной копией `.previous`. Сборка из исходников показывает путь к скачанному portable EXE. Скрипты находятся в ASAR unpack, конфигурация читается в UTF-8.
- Linux: `updates.py` — совместимый с Python 3.5 / cryptography 1.7 транспорт; `update_ui.py` — GTK и workers. Проверенный DEB устанавливается через `gdebi-gtk`, если он есть, иначе `pkexec /usr/bin/dpkg -i`. Запрос прав выполняет ОС. После успешной установки UI просит закрыть и снова открыть приложение; работающие сеансы принудительно не закрываются. Без доступного системного установщика отображается ошибка, а не фиктивный успех.

Это собственная подпись списка релизов, не Authenticode Windows. Приватный ключ релизов не совпадает с SSH-ключами пользователя, не хранится в vault, репозитории, сайтах или исходных архивах.

## Выпуск и деплой

Три корневых PowerShell-скрипта используют `tools/build.py`. Укажите `-Version 0.10.1 -Deploy`, чтобы задать общую версию и после успешных unit tests и native-сборок подписать и выложить релиз/сайт. `-SourceOnly` и `-SkipTests` несовместимы с публикацией. GUI добавляется `-Smoke`. `-Plan` показывает выбранную версию и признак публикации без записи файлов. Полная справка по ключам доступна через `Get-Help ./build-all.ps1 -Full`.

Параметры: `-DeployHost`, `-DeployUser`, `-DeployRoot`, `-SigningKey`, `-ReleaseNotes`. Адрес/логин/корень берутся из частного `deploy.json` рядом с ключом; также можно задать `ASTRATERM_DEPLOY_HOST/USER/ROOT` или параметры командной строки. Пароль FTPS запрашивается через getpass и не сохраняется. Для публикации Python требует `cryptography`; использующая FTPS библиотека — штатная. На Windows ключи защищены ACL текущего пользователя, на Unix — mode 0600. Значение по умолчанию для ключа: `%LOCALAPPDATA%/AstraTermBuild/release-signing.pem` либо `~/.local/share/AstraTermBuild/release-signing.pem`.

Для нового проекта `python tools/release.py --init-key` создаёт ключ вне checkout и обновляет публичный ключ в product.json; после этого обязателен `python tools/sync_shared.py`. **В существующем проекте ключ не перевыпускать:** уже установленные приложения доверяют прежнему публичному ключу. Сохранять резервную копию приватного ключа вне публичных/облачных исходников. Без него нельзя подписывать новые обновления для установленных клиентов.

`tools/release.py` сверяет артефакты с `build.json`, соединяется по FTPS с проверкой сертификата и шифрованием данных. Пакеты публикуются по неизменяемым `/releases/<version>/<name>`: повторная попытка допустима только при том же hash. Затем assets/альтернативы, открытые сведения релиза и подписанный latest.json; домашняя страница — последней. Старые изменяемые файлы сохраняются вне webroot в частном каталоге резервных копий; при неудачной замене исходный файл восстанавливается. Рекурсивного удаления файлов хостинга нет.

Публикация одной ОС сохраняет проверенную запись другой ОС из предыдущего списка. Первый публичный выпуск требует оба готовых пакета для двух кнопок сайта. Увеличивайте версию перед изменением уже опубликованных бинарников. `build-summary.json.deployment` показывает итог деплоя отдельно от платформенных проверок.

Выкладка сайта также обновляет PHP-панель `/admin/`. Её CSS и обработчик статистики публикуются до точки входа. Хеш пароля и журналы доступа находятся вне каталога сайта и сохраняются между релизами. Описание подсчёта и входа есть в [документации сайта](../website/production/README.md#статистика-сайта).

## Проверки

`tests/test_updates.py` и `windows/tests/updates.test.cjs`: общий подписанный контракт, подмена подписи/URL, версии, границы, повреждение/обрыв/лишние байты скачивания. `tests/test_release_deploy.py`: откат, неизменяемые пакеты и порядок commit. `tests/smoke_updates.py`: реальные GTK-кнопки со синтетическими метаданными и подменённым системным установщиком. `windows/tools/smoke-update-install.ps1`: реальное ожидание, hash, backup, замена и перезапуск двух локально скомпилированных безвредных fixtures. Пользовательские SSH-ключи/агент не используются.
