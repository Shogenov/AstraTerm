# Перенос подключений и паролей

Импорт доступен в Linux и Windows: меню слева → Файл → Импорт подключений. Перед записью появляется список подключений, папок, привязок к профилям и ограничений. Отмена предпросмотра ничего не сохраняет. Для сторонних файлов существующие настройки папок сохраняются; восстановление AstraTerm JSON сохраняет прежнюю семантику явных параметров папки; импортированные сессии используют свои параметры. Повторный импорт того же источника обновляет записи со стабильными ID.

| Источник | Файл | Что переносится |
| --- | --- | --- |
| MobaXterm | `.mxtsessions`, отдельная `.moba` | SSH, Telnet, RDP и VNC, папки, порт, пользователь, ссылки на учётные данные, путь ключа, X11/сжатие, поддерживаемая SSH-цепочка |
| MobaXterm | открытый текстовый экспорт Stored Passwords | Именованные `профиль(пользователь) = пароль` и адресные `ssh22:пользователь@сервер = пароль`, включая нестандартный порт |
| Termius | CSV | Label/Name, Address/Hostname/IP, Port, Protocol, Username/User, Password, Group/Groups, IdentityFile/KeyFile |
| Termius | OpenSSH config, в том числе результат `termius export-ssh-config` | Простые блоки Host, поддерживаемые параметры SSH и папка `SSH config`. Include/Match, ProxyCommand и несколько ключей требуют ручной настройки; импорт с ними отклоняется |
| Ásbrú Connection Manager | `.yml`, `.yaml`, экспорт выбранных соединений или полный YAML | Узлы `environments` либо `__PAC__EXPORTED__`, родительские UUID/папки, SSH/SFTP, Telnet, RDP, VNC, Mosh, параметры адреса и ключа |
| AstraTerm | JSON схемы 1/2 | Прежний импорт подключений сохраняется; пароли в этот JSON не входят |

Это импорт файлов. Приложение не читает локальную базу или облачный аккаунт Termius. Для произвольного JSON/зашифрованного резервного файла Termius нужна отдельная спецификация формата. Возможность импортировать протокол не означает, что его клиент уже перенесён в Windows; ограничения перечислены в [сравнении платформ](PLATFORM_PARITY.md).

## MobaXterm и соответствие профилей

Можно выбрать файл сессий и файл паролей одновременно либо импортировать их по очереди. `[Production]` в поле пользователя сессии связывается с `Production(ops)` в экспорте паролей: именованный профиль задаёт пользователя и пароль. Ссылка имеет стабильный ID и сохраняется в базе сессий. Пароль адресной записи применяется только к совпадающим протоколу, порту, пользователю и адресу; пароль конечного узла не используется для SSH-шлюзов. Совпадение только по имени сервера не считается достаточным.

Отсутствующий профиль показывается в предпросмотре. Подключение не подменяет его другим профилем: нужно импортировать недостающие учётные данные либо выбрать другой профиль в редакторе сессии. Указанный в сессии ключ и профиль пароля — отдельные параметры: можно использовать ключ и получить имя пользователя из профиля. В предпросмотре есть выбор существующего SSH-профиля AstraTerm сразу для всех импортируемых SSH-сессий.

В Windows `_MyDocuments_` раскрывается в системную папку «Документы» при импорте и при открытии ранее импортированных SSH-сессий. Это учитывает перенаправление папки, включая OneDrive. Для `_CurrentDrive_` и Windows-путей на Linux выберите файл ключа на текущем компьютере. В Windows предпросмотр позволяет явно отключить неподдерживаемый X11 у импортируемых SSH-сессий. Прокси и шлюзы удалённого рабочего стола, которые нельзя перенести точно, помечаются; такие подключения заблокированы до проверки параметров в редакторе. WSL и другие неподдерживаемые типы показываются в отчёте и пропускаются.

В Windows откройте ☰ → Файл → Пароли из MobaXterm. Выберите `MobaXterm.ini` в предложенной папке «Документы» или AppData. Для portable-версии можно выбрать файл рядом с MobaXterm.exe. Введите мастер-пароль MobaXterm под той же учётной записью Windows, которая сохранила пароли. Для закрытого хранилища появится отдельный запрос мастер-пароля AstraTerm. Предпросмотр показывает совпадения и число пропущенных профилей с неподдерживаемыми полями. Для паролей из другой учётной записи или версии, в которой пароли отсутствуют в INI, используйте текстовый экспорт MobaXterm на компьютере-источнике и выберите его через «Импорт подключений». Для переноса самих подключений выберите `.mxtsessions` в том же пункте.

Записи без пароля пропускаются, в том числе записи MobaXterm 25.x, где сохранился только префикс шифрования. В предпросмотре показывается их количество. Остальные записи проходят обычную проверку и сопоставление с подключениями.

Для переноса из командной строки запустите `.\.venv\build\Scripts\python.exe tools/import_mobaxterm.py` для предварительного просмотра и добавьте `--apply` для записи. Перед записью скрипт создаёт резервную копию настроек и зашифрованного хранилища. После записи перезапустите AstraTerm, чтобы он перечитал файлы.

С `--reset-vault --apply` скрипт создаёт новое хранилище под указанным новым мастер-паролем, заменяет набор учётных данных импортированными профилями и убирает ссылки на удалённые профили. Сессии с однозначным соответствием получают новые привязки.

## Хранилище паролей

При первом сохранении паролей создаётся мастер-пароль с повторным вводом; минимум 10 символов. Файл `credentials.vault.json` находится рядом с `sessions.json`, но отдельно от него. Пароли шифруются библиотечным AES-256-GCM; ключ получается через PBKDF2-HMAC-SHA256, 600000 итераций, случайную соль 32 байта. Каждая запись файла использует новый случайный nonce 12 байт и тег 16 байт. Параметры задаёт `shared/product.json`. Linux использует штатную `cryptography`, Windows — Node `crypto`. Формат общий и проверяется в обе стороны тестовыми файлами двух реализаций.

Мастер-пароль не сохраняется. После разблокировки ключ и учётные данные доступны в памяти приложения до закрытия или пункта Инструменты → Хранилище учётных данных → Заблокировать. Блокировка не обрывает уже работающие терминалы. Неверный пароль, повреждённый тег и устаревшая версия файла не дают доступа к секретам; запись выполняется атомарно с блокировкой и проверкой ревизии. В Linux права файла — `0600`.

Сессии, обычный экспорт JSON, argv, окружение процессов и журналы паролей не содержат. В Linux OpenSSH 7.4 получает пароль через частный askpass-сокет с проверкой владельца; помощник запуска сохраняет завершение дочернего SSH-процесса. Автоматический SFTP получает пароль из того же разблокированного хранилища. В Windows пароль получает SSH2, а SFTP использует тот же аутентифицированный транспорт. Проверка ключа SSH-сервера остаётся обязательной. Одноразовые коды не заполняются сохранённым паролем автоматически.

RDP с 0.7.0 встроен в обеих ОС и переиспользует пароль профиля через частный канал. VNC остаётся внешним клиентом без автоматической передачи пароля. Подробнее в [RDP.md](RDP.md). Для SSH-ключей действуют ssh-agent и профиль ключа.

В меню **Инструменты → Хранилище учётных данных** доступны два действия в Windows и Linux:

- **Изменить мастер-пароль** запрашивает текущий и дважды новый пароль. AstraTerm повторно шифрует сохранённые профили с новой солью и сохраняет их ID.
- **Сбросить мастер-пароль** создаёт пустое хранилище с новым паролем и удаляет сохранённые пароли SSH/RDP. Подключения и ключи сохраняются. После повторного импорта с теми же ID профили снова доступны связанным сессиям. Для других профилей назначьте их в настройках подключения.

Новый мастер-пароль содержит не менее 10 символов. Изменение и сброс записываются атомарно. После успешной записи хранилище открыто до выхода или блокировки.

## Ásbrú и ограничения

YAML разбирается безопасным загрузчиком; повторяющиеся ключи, неизвестные теги, циклы папок и слишком сложная структура отклоняются. Shell-команды, Expect, локальные скрипты, дополнительные параметры клиентов и автоматически запускаемые команды не исполняются. Непустые дополнительные параметры клиента требуют проверки и блокируют подключение, поскольку в них может находиться обязательный маршрут. Непереносимый прокси не превращается в прямое подключение.

Открытый пароль из YAML можно сохранить в мастер-хранилище. Для переноса паролей Ásbrú экспортируйте YAML без опции шифрования. Размер одного исходного файла ограничен 8 МиБ, число выбранных файлов — восемью, число сессий/профилей — 10000. Поддерживаются UTF-8/BOM, UTF-16 с BOM и запасное чтение Windows-1251.

## Контракты и первичные источники

С 0.9.0 пароли и SSH-ключи управляются через единое «Хранилище учётных данных». Тип пароля хранится зашифрованно; старые импортированные записи без типа остаются совместимыми с SSH/RDP и сохраняют ID/ссылки. Сам ключ и правила ssh-agent не изменяются. [Управление профилями](HOST_STATUS.md).

Публичные синтетические примеры: `shared/contracts/imports.json` и `vault.json`. Настоящие файлы пользователя не включаются в тесты и поставку. Проверки: `test_importers.py`, `test_vault.py`, Windows `importers.test.cjs`/`vault.test.cjs`, native `smoke_imports.py` и `smoke-imports.cjs`.

- [Исследование формата автором .mxtsessions](https://gist.github.com/Ruzgfpegk/ab597838e4abbe8de30d7224afd062ea): позиции полей MobaXterm дополнительно сверены с предоставленными образцами.
- [Termius: CSV и SSH config](https://docs.termius.com/getting-started/import-existing-hosts), [официальный legacy CLI](https://github.com/termius/termius-cli): поддерживаемые файловые пути миграции; не обещание формата любой резервной копии Termius.
- [Ásbrú: экспорт YAML](https://github.com/asbru-cm/asbru-cm/blob/master/lib/PACMain.pm), [структура соединений и собственное шифрование](https://github.com/asbru-cm/asbru-cm/blob/master/lib/PACUtils.pm).
